# План переписывания на Go

**Вход:** `docs/reference/ts-manager-contract.md` (поведение + 10 обязательных
исправлений), решение `docs/decisions/0001-two-repos.md`.
**Приоритет владельца:** вес и холодный старт. Один бинарник на всё.
**Стек:** Go 1.27, `github.com/modelcontextprotocol/go-sdk` v1.8.0
(протокол по умолчанию `2026-07-28`), stdlib для HTTP и шаблонов, без внешних
веб-зависимостей.

## Ворота

Одна команда на весь проект:

```bash
E2E_BASE=http://127.0.0.1:9091 go test ./e2e -v
```

Плюс `go build ./... && go vet ./... && go test ./...` на каждом коммите.
Этап считается принятым, только когда e2e зелёный в strict-режиме.

## Дашборд

Отдельный трек, начинается после этапа 4 (нужны живые данные: статусы наборов,
health, вызовы). Экран показывает то, чего сейчас нет ни в одной вкладке:
состояние всех наборов разом, здоровье серверов, поток вызовов с задержками,
незаполненные переменные. Дизайн требует приёмки до реализации — по правилам
проекта UI не пишется без согласованного макета.

## Что решаем заранее

- **Формат `servers.json`:** оставляем совместимым с lazy-mcp (это контракт
  между менеджером и набором). Новые поля — только опциональные.
- **Порты:** 9100–9199 как диапазон публикации; валидация обязана совпадать.
- **Auth:** без `MCPRIG_PASSWORD*` и без `MCPRIG_PROXY_SECRET` менеджер не
  стартует, кроме явного `MCPRIG_AUTH=off`.
- **Секреты:** в ребёнка только `$VAR` его серверов; `env.json` не наследуется.
- **Логи:** хвост файла, фильтр по точному имени сервера.

## Решено

1. «Вызов» — собственный счётчик в `invoke_command` (`internal/stats`), не
   разбор лога: лог набора не содержит клиента и не переживает рестарт.
2. Репозиторий — Gitea, `<host>/mcprig`, операции через `gt`.
   Путь модуля — `github.com/akrhin/mcprig` (снято 2026-11-11: резолвится,
   `proxy.golang.org/.../@latest` → `v0.3.8`).
3. Формат конфига — только JSON (`servers.json`): это общий формат с lazy-mcp и
   родной формат секции `mcpServers` у клиентов, менять его ради TOML значило бы
   ломать копипаст из чужих README и тянуть парсер в бинарник без зависимостей.
4. Codemap из `lazy-mcp` удалён; для этого репозитория — когда код перестанет
   двигаться.
5. Хендшейк к stdio-серверам идёт через `initialize` (ревизия `2025-11-25`), а не
   через stateless `server/discover` из SEP-2575: сервер на Python SDK ≤ 1.9 не
   знает нового метода, не отвечает и падает в приёмном цикле (pydantic
   `ValidationError`), поэтому клиент ждал 15 с и получал
   `context deadline exceeded`. `initialize` понимают все, подписка на
   `tools/list_changed` объявляется и в нём, так что потерь нет. HTTP-транспорт
   остался на современном хендшейке: там stateless-обнаружение и есть смысл.
6. GitHub — публичное зеркало `akrhin/mcprig` (push-зеркало из Gitea, мастер и
   теги уезжают сами). Релиз там собирает `.github/workflows/release.yml`:
   goreleaser идёт с `--skip=publish`, архивы и `checksums.txt` загружает `gh`
   (`.goreleaser.yaml` остаётся один — с `gitea_urls` и `draft`). Публичный
   репозиторий — минуты Actions бесплатны, так что дубль сборки ничего не
   стоит, а локальные минуты Gitea тратятся один раз, как раньше. Тег без
   пушнутого workflow запускается вручную: `gh workflow run release.yml -f
   tag=vX.Y.Z`. Контрибутор дашборда — `V0rt` (write).
7. Ответ тула чистится от секретов на проводе (`internal/mcpserver/redact.go`):
   значения `env`/`headers` с секретным именем (`key|token|secret|pass|auth|credential`,
   длина ≥ 8, префикс `bearer ` срезается) заменяются на `***` в текстовом
   результате до записи в `/stats` и до выгрузки в `tool-out`. Структурированные
   результаты не трогаем — подмена полей ломает клиентов, которые по ним работают.
   Причина: апстрим повторяет ключ в тексте ошибки (tavily вернул `api_key`
   в `missing`-ответе), и ключ попадал в контекст агента.
8. Health панели: бюджет загрузки (30 с) дольше внутреннего бюджета набора
   (`healthTimeout` 15 с). Пока они совпадали, после рестарта весь набор показывал
   `context deadline exceeded`, и ошибочный снимок жил в кэше ещё `healthTTL`.
9. Логин отвечает `400` на пустые поля, а не `401`: `401` — это «неверный пароль»,
   и клиенту не надо угадывать разницу. Создание набора отдаёт выданный токен
   один раз в `201`; в списке `/api/sets` его нет — иначе его берут из
   `registry.json`, где рядом лежит уже отозванный ключ, и получают `401`.
10. `list_commands` без `server`/`servers` — ошибка, называющая аргументы, а не
   «все серверы»: рецепты со `servers=[…]` поддерживаются, аргументы инструмента
   всегда лежат в `parameters`.

## Песочница для недоверенных MCP (этапы 0–1 сделаны, 2026-11-10)

Полный разбор — `docs/research/untrusted-mcp-sandbox.md` (модель угроз,
варианты, источники, 381 строка). Коротко:

Граница одна: `internal/downstream/connect.go:107-168` — `exec.Command` на :132,
env на :134-142. Песочница — это префикс argv, транспорт не меняется.

| вариант | что даёт | цена |
| --- | --- | --- |
| `bwrap` (userns) | нет сети, нет `/home`, своё дерево ФС; 10 мс; без root; лимиты `prlimit` внутри пространства имён | целые флаги (`--unshare-*`, `--remount-ro`), а не `--unshare-all`; bind-ы под node/python подбирать руками |
| Docker/Podman rootless | лимиты и образы из коробки, `--network none`, read-only | общий kernel — не граница для недоверенного кода; образ на каждый сервер; CVE-2026-55887 в docker/mcp-gateway показал, что сборка argv — тоже attack surface |
| gVisor (`runsc`) | сильнее контейнера, обычные Linux-бинари | совместимость node/python, отдельная эксплуатация |
| microVM (Firecracker/microsandbox) | сильнейшая практичная граница | KVM, образы, vsock; инфраструктура |
| Landlock + seccomp | вторая стенка внутри своей же песочницы, fallback | сеть только по портам, не по адресам; нужен re-exec-хелпер |
| systemd-run --user | готовые свойства юнита | `--scope` не принимает `ProtectHome` (проверено), lifecycle уходит в systemctl |
| WASM | capability-модель, мгновенный старт | зрелого рантайма под произвольный node/python MCP нет |

Этапы:
0. Сделано (`f398872`): whitelist env для stdio — `envAllow` + фиксированная
   база в `internal/downstream.EnvFor`, `Env` ставят `serve`, `stdio`, `warm`
   и панель; предупреждение на `npx -y`/`uvx` без пина (`Server.Warnings()`,
   видно в `mcprig doctor`); сервер с тегом `untrusted` без песочницы не
   подключается — остаётся в списке с `_configError`, API панели отвечает 400.
1. Сделано (`f398872`): `Server.Sandbox{mode,onUnavailable,ro,rw,network,
   memoryMb,pids,timeoutSec}`, `internal/sandbox.Wrap` (bwrap + `prlimit`
   внутри userns), fail-closed `onUnavailable:"deny"`, `timeoutSec` на вызов.
   Проверено на хосте: ядро 6.12.115, userns включён, сеть закрыта, `~/.ssh`
   недоступен, запись в `/` отбита. В Docker-образы bwrap не входит — см.
   `docs/en/install.md`.
2. Docker-режим и управляемый egress (allowlist хостов, инъекция секретов).
3. microVM — когда появятся серверы, которым нужен полный OS.

Изоляция не лечит tool poisoning, confused deputy и prompt injection — для них
отдельные механизмы (пиннинг `tools/list`, allowlist инструментов).

Проверка — `scripts/sandbox-e2e.sh` (10 проверок + Go-тест на env): `~/.ssh`,
`registry.json`, curl наружу, запись в `/` и `/etc`, запись в `rw`, `env`,
fork-бомба (`pids`), `/proc/1/root`, `mount`, unix-сокет, лимит памяти.

## Долг, принятый сознательно (2026-11-09)

Ревью паладина и арбитра по `4399e9e` закрыто правками; ниже — то, что
оставлено с открытыми глазами, с причиной:

Занятость явного порта закрыта в `674d792`: `POST /api/sets` теперь тоже
отвечает `409 «порт N занят процессом»`, а тесты реестра выбирают свободный
порт через `freePort(t)` вместо фиксированного `"port":9100`.

- **`caps.Logging`** в browse: поле deprecated в SDK (SEP-2577), исчезнет в
  следующей ревизии протокола — тогда убрать.
- **Плагин маршрута** `~/.config/opencode/plugins/mcprig-route.ts` загружается
  процессом панели: в `~/.local/share/opencode/log/opencode.log` есть строка
  `msg="loading plugin" id=…/mcprig-route.ts … role=server`, а новая сессия
  панели цитирует подсказку «MCP живёт за mcprig…». `opencode plugin list` для
  проверки не годится: команда печатает список того сервера, к которому
  подключился сам CLI, и при живом инстансе может ответить
  `No plugins found`.
- **Выгрузки `tool-out`** чистятся по TTL 24 ч и потолку 256 MiB (`5a98eea`);
  `stdio` чистку не запускает — процесс короткоживущий.

Закрыто: холодный обход `${VAR}` (`4cad5cd`) — имена резолвятся параллельно,
до 8 сразу, порядок значений и текст `remoteError` прежние; первый
`GET /api/env`, старт набора, probe и browse больше не ждут 5 с на переменную.
Очередь на scrypt (`4753918`) — одновременно считаются 2 проверки, считающих и
ждущих вместе не больше 8, сверх — сразу 429 с `Retry-After: 5`. `goreleaser
check` (`b2ce4cb`) — шаг в джобе `release` перед `release --clean`, невалидный
`.goreleaser.yaml` роняет джобу.

## Открытые вопросы

- **Логи наборов без логина.** `/api/sets/:id/logs` (ring 2000 строк) работает
  только под admin-сессией, `journalctl --user -u mcprig` пуст: мониторинг
  чужого набора возможен только с паролем панели. Решение не принято.
- **Тонкий CLI.** `mcprig` без аргументов = `serve` с
  `~/.config/mcprig/servers.json` и падает `no such file`, `mcprig panel --help`
  отвечает «не принимает аргументов»; управление — только HTTP API с
  CSRF-проверкой Origin. Решение не принято.

Каналы — только архивы goreleaser (обёртки npm/PyPI/crates не заводим);
образы Docker публикуются в GHCR — `ghcr.io/akrhin/mcprig` (реестр Gitea закрыт и раздачей не служит)
(`latest` = slim 32 МБ, `latest-full` = с node и python, 334 МБ, плюс теги
`0.3.7-slim`/`0.3.7-full`);
путь модуля остаётся `github.com/akrhin/mcprig`, публичный репозиторий на GitHub —
зеркало `akrhin/mcprig` (п. 6 выше).
