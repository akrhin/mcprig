# Полный аудит репозитория (2026-11-18)

Запрос владельца: «пробегись и посмотри проблемы. жду отчет» — аудит без сабов,
формат «старший разработчик, которого поднимут ночью». Отчёт дан в чате и
зафиксирован здесь; код в ходе аудита не менялся.

## Что делает репозиторий и какая нагрузка принята

Один статический бинарник работает в двух режимах: `mcprig panel` держит реестр
серверов и наборов и web-панель, `mcprig serve` поднимает один процесс на набор
(`internal/manager/runtime.go:174`). У набора свой порт, bearer-ключи, группа
процессов, statistics и tool-out. Клиент видит девять мета-инструментов вместо
всего каталога инструментов. Конфиг, секреты и токены лежат в одном каталоге
состояния.

Нагрузка: один хост, один оператор, несколько долгоживущих наборов; на хосте
два набора по 8–13 серверов и около 970 инструментов. Вкладка панели опрашивает
состояние/здоровье/лог раз в 5–30 с. Один клиент может послать `invoke_many` с
8 вызовами, на сервер одновременно до 4 вызовов. CLI — короткие одноразовые
команды. Это не мультитенантный сервис: один вход в панель и одна граница доверия.

## Must fix

Критичных находок нет: не найден путь, который теряет данные, обходит ключ или
даёт неавторизованному клиенту изменить реестр в принятой модели.

## Should fix

1. **Карта неудачных входов растёт без реального предела — `internal/manager/auth.go:441,451`.**
   `loginFailedOne` чистит только просроченные записи и только когда их больше
   1024. 100 тыс. разных IP за минуту создают 100 тыс. живых записей — чистка их
   не коснётся. Доказательство: условия в `loginFailedOne` и `len(a.loginFails) > 1024`.
   Минимум: при превышении 1024 удалять самую старую запись, даже если её окно
   ещё живо. Без правки публичная панель может уйти в рост памяти при
   распределённом переборе паролей.

2. **Карта тормоза refresh не имеет очистки — `internal/mcpserver/ratelimit.go:50-63`, `internal/mcpserver/manager.go:125`.**
   `mayRefresh` пишет `refreshAt[identity + server]` навсегда; в отличие от
   корзин лимита (`ratelimit.go:15-27`), здесь нет ни TTL, ни потолка. Минимум:
   удалять записи старше `catalogRefreshEvery` при каждом вызове. Без правки
   долгоживущий набор медленно теряет память на каждого нового клиента.

3. **Карта состояний webhook не чистится при удалении набора — `internal/manager/notify.go:56,70-108`, `internal/manager/api.go:1625-1643`.**
   `notifier.last` ключует по `setID/server`; `apiSetDelete` зовёт `rt.Forget(id)`,
   но не чистит notifier. Минимум: добавить `notifier.forgetSet(id)` и звать его
   из `apiSetDelete`. Без правки — медленный рост и подавление первого события
   у набора, повторно созданного с тем же id.

4. **Маскировка секретов зависит от имени поля — `internal/config/secrets.go:10,15-36`.**
   Маскируются только env/заголовки с именем из `(key|token|secret|pass|auth|credential)`.
   Токен в `GITHUB_PAT` или `CF_ACCESS` не попадает в список, и апстрим, который
   его печатает, кладёт секрет в текст ошибки панели. Минимум: разрешить явно
   объявлять дополнительные секретные значения или маскировать все значения
   защищённых полей.

5. **README предлагает старый релиз — `README.md:34`, `README.ru.md:34`.**
   Quick start качает `v0.6.3`, хотя выпущен `0.6.5`, а PR #32 готовит `0.6.6`.
   Минимум: ссылка на `releases/latest`. Без правки новый пользователь ставит
   версию без последних исправлений.

6. **Кэш здоровья может ждать вечно после паники — `internal/manager/health.go:80-113`.**
   `healthCache.get` ставит `e.wait` до вызова `load` и снимает его после. Паника
   в `load` оставляет канал открытым: `ServeHTTP` восстанавливается, но следующий
   запрос здоровья ждёт его вечно. Минимум: снимать и закрывать канал через
   `defer` или восстанавливаться внутри лидера.

7. **Приёмка не стоит в воротах CI — `scripts/acceptance/panel.cjs`, `.github/workflows/ci.yml`.**
   37 браузерных шагов зелёные, но CI их не гоняет: в раннере нет браузера.
   Go-тесты поведение `web/app.js` не покрывают. Минимум: отдельная задача с
   Playwright или обязатель проверка в хостовом конвейере. Без правки GUI может
   сломаться при всех зелёных проверках.

8. **Кэш статистики очищается целиком — `internal/stats/history_query.go:438-462`.**
   При достижении `cacheMax` весь парк файлов выбрасывается, и следующий опрос
   панели парсит историю всех наборов. Минимум: вытеснять старые записи до
   порога, а не обнулять карту.

## Nice to have

9. **Метки переподключения могут занять весь хвост лога — `internal/downstream/serverlog.go:89-105`.**
   `Writer` зовёт `markStart()` при каждом переподключении к тому же серверу.
   Минимум: помечать только реальный выход прошлого процесса или ограничить
   частоту меток.

10. **Несовпадение ответов `tool-out` — `internal/httplisten/httplisten.go:209-260`.**
    Просроченная выгрузка даёт 410, отсутствующий `.owner` — 404 с тем же
    текстом для всех имён. Утечки нет; пункт записан для полноты, менять не
    нужно.

## Verdict и Lean

Ветку можно мержить: найденные пункты — гигиена памяти, одна ошибка в тексте
документации и одна недостающая проверка в CI; блокирующего дефекта в
прослеженных потоках нет. До релиза 0.6.6 стоит закрыть пункты 1, 2 и 5.

Lean: -0 зависимостей; около 40 строк — длинный блок команд установки в двух
README дублирует `docs/en|ru/install.md`, его можно заменить ссылкой.

## Не проверялось

Визуальные детали каждого экрана (только автоматический обход), бинарники под
macOS/arm64, образ Docker в работе, живой OAuth с реальными провайдерами,
песочница под ограничивающим ядром, нагрузочный тест с большим числом
одновременных клиентов.
