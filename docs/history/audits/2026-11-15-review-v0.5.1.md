## 5. Баг `quasar`: пустой набор

Со скриншота: набор `quasar` (`:9112`, stopped, `SERVERS 1`), единственный
сервер `time`, баннер «сервер time последний в наборе quasar: удалите набор или
добавьте другой».

Воспроизведено на живом инстансе (пустой каталог данных, сервер `cmd/testmcp`):

```
POST /api/sets {"name":"empty","port":9151}
  → 400 в наборе должен быть хотя бы один сервер
PUT  /api/sets/quasar {"servers":[]}
  → 400 в наборе должен быть хотя бы один сервер
PUT  /api/sets/quasar {"servers":null}
  → 200, набор не изменился (null = «поле не трогать»)
DELETE /api/servers/time            # единственный сервер набора
  → 400 сервер time последний в наборе quasar: удалите набор или добавьте другой
```

Тупик: сервер удалить нельзя, а удаление набора уносит ключ (токен живёт в
`sets[].keys[]` и показывается один раз при создании) и порт. Обхода через API нет.

Инвариант держат четыре места: `validate.go:359-366`, `validate.go:378-380`,
`store.go:399-401` и распознавание отказа по русской подстроке в
`api.go:1296-1300`.

**Рантайм пустой набор уже умеет.** `mcprig serve` с `"servers": []` стартует
(`прокси слушает … servers=0`), `/healthz` отвечает 200, `initialize` отдаёт
`serverInfo` и `tools.listChanged`, мета-тулы доступны.
`BuildSetConfig` (`setconfig.go:66-104`) пустой список не отвергает. UI уже несёт
пустое состояние «в наборе нет серверов» (`app.js:331-332`) — просто недостижимое.

Вывод: запрет — не требование рантайма, а несогласованный инвариант. Решение и
его последствия — `docs/history/decisions/0004-empty-sets.md`.

## 6. Чистая установка: статистика и панели

`/api/calls` — `{"calls":[],"counters":[]}`, `/api/stats` — нули без серий,
`/api/env` — `{"vars":[]}`, экспорт реестра — `{"version":1,"servers":[],"sets":[]}`.
