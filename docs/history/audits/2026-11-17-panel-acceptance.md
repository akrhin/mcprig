# Приёмка панели 0.6.5: четыре расхождения и их причины

Владелец проверил выпущенный бинарь на своём инстансе (`MCPRIG_DATA_DIR=/tmp/opencode/verify-data`,
порт 9112, `MCPRIG_AUTH=off`, `?mock=1`) и нашёл четыре места, где панель ведёт себя
не так, как обещал отчёт предыдущей полосы (`docs/history/audits/2026-11-17-panel-pages.md`).
Правки — в `web/`, ветка `fix/panel-acceptance`. `CHANGELOG.md`, `CHANGELOG.ru.md` и
`docs/history/index.md` правит тот, кто сводит ветку: нужные строки выписаны в конце.

Проверял по реальному рендеру: свой инстанс (`MCPRIG_DATA_DIR=/tmp/opencode/pages-data`,
порт 9099, `MCPRIG_AUTH=off`) и демо-данные `?mock=1` из `web/mock/*.json`. Ширины
375, 768 и 1280, языки EN и RU, схемы dark и w98 (Win98 поверх своих 10–11 px).

## 1. Неизвестный маршрут открывал последний набор

Причина не в одной строке, а в трёх местах сразу:

- `pageOf()` (`web/app.js`) отдаёт `sets` для любого незнакомого адреса — так и было задумано;
- `route()` приводил панель к адресу только когда в адресе назван набор
  (`if (r.page === 'sets' && r.set)`), поэтому на `#/nonsense` ничего не менялось:
  оставался `st.sel` от прошлого клика;
- `renderChrome()` считал `onSets = st.page === 'sets'` и на любой странице наборов
  показывал шапку набора и вкладки. **Списка наборов в панели не существовало вовсе** —
  списком был только левый рельс, а `#/sets` открывал обзор последнего выбранного набора.
  Это и видел владелец: `#/sets` на скриншоте `design/ui/panel-pages/after-sets-1280-dark-en.png`
  предыдущей полосы — обзор набора `main`, а не список.

Что сделано:

- появилось состояние `st.list` — «страница наборов без набора в адресе»; `route()`
  ставит его из адреса и в этом случае обнуляет `st.sel`;
- в `#page-sets` добавлен блок `#sets-list`: таблица **Set** (имя и `:port`), **State**,
  **Servers**, **Keys** — строка ведёт на `#/set/<id>`; данные те же, что уже приходят
  в `/api/state`, ни одного нового поля бэкенда;
- `renderChrome()` в режиме списка прячет шапку набора, вкладки и **все панели вкладок**
  (`applyTab(null)`), показывает `#sets-list` и рисует его же (`renderSetsList()`);
- `loadState()` в режиме списка не выбирает первый набор автоматически — раньше
  `indexOf(null) === -1` тянул `select(ids[0])` и список немедленно превращался в набор;
- `select()` снимает режим списка и вызывает `renderChrome()`, поэтому шапка и вкладки
  возвращаются вместе с набором;
- крошка в режиме списка называет страницу (`Наборы`), а не прочерк.

Проверено в браузере: `#/nonsense` → список, `#/sets` → список, `#/set/main` → набор,
клик по строке списка кладёт `#/set/main` в историю, «назад» возвращает к списку.

## 2. Заголовок окна не следовал странице

Было: `document.title = st.sel ? t('title.set', {name: st.sel}) : t('title.panel')` —
`st.sel` переживал переход на другую страницу, поэтому `#/` и `#/sets` назывались
`mcprig — set main`, а по-английски ещё и `set` вместо имени набора.

Стало (`setTitle()`, вызывается из `renderChrome()`, `setTab()` и `select()`):

| адрес | заголовок EN | заголовок RU |
| --- | --- | --- |
| `#/` | `mcprig — Overview` | `mcprig — Обзор` |
| `#/sets` | `mcprig — Sets` | `mcprig — Наборы` |
| `#/stats/7d` | `mcprig — Statistics` | `mcprig — Статистика` |
| `#/servers` | `mcprig — All servers` | `mcprig — Все серверы` |
| `#/vars` | `mcprig — Variables` | `mcprig — Переменные` |
| `#/set/main` | `mcprig — set main` | `mcprig — набор main` |
| `#/set/main/keys` | `mcprig — set main · Keys` | `mcprig — набор main · Ключи` |
| `#/nonsense` | `mcprig — Sets` | `mcprig — Наборы` |

Ключ `title.panel` сокращён до `mcprig` — из него теперь собирается «`mcprig` — страница».
Набор называется по имени, а не по `id`.

## 3. Мок отставал от выпуска

`web/mock/state.json` отвечал `version: 0.6.4`, живой `/api/state` — `0.6.5`; подвал
панели показывает именно это поле, так что демо-режим врал о версии. Исправлено на
`0.6.5`. Остальные поля сверены тем же скриптом, что и в прошлый раз
(`/tmp/opencode/mock-parity.py`: собирает все `json:"…"` теги из `internal/` и имена из
map-литералов, затем walk по `web/mock/*.json`): `mock: все поля есть в живых ответах
(257 имён сверено)`. Ключи `reloadErrors`, `failed`, `throttledTools` скрипт пропускает —
их ключи это id наборов, а не поля.

## 4. «Latest calls» на обзоре хоста на 375 px

Вкладку **Calls** набора владелец признал годной и просил не трогать — она и не
тронута: у `#calls-table` прежняя раскладка `data-label`.

Плохо было на обзоре хоста: `#host-calls-table` — настоящая таблица из шести колонок,
на 375 px она сжималась и подписи TIME/SET/SERVER/TOOL/MS/STATUS перемешивались со
значениями. Теперь при ширине ≤ 760 px каждая строка — карточка, запись читается сверху
вниз:

```
11/08, 23:14                              ● ok
main                              socraticode
codebase_search                           329
```

Время (моно, приглушённое) и статус — первая строка; набор и сервер — вторая;
инструмент (моно, переносится) и миллисекунды — третья. Ячейки получают `data-col`
в `renderHostCalls()`, раскладка — в `web/app.css` под `#host-calls-table` (правило
привязано к id этой таблицы, поэтому вкладку **Calls** не задевает). На 768 и 1280
таблица остаётся таблицей: свёртка включается на ≤ 760 px.

## Отклонения и то, что осталось как есть

- **Win98** держит свои 10–11 px и 21–24 px хром — это зафиксированное решение
  предыдущей полосы (пункт 6 в `2026-11-17-panel-fixes.md`): тема воспроизводит систему,
  а не современный интерфейс. Правило «не мельче 12 px / цель ≥ 32 px» выполняется в
  четырёх схемах Default; карточки вызовов в Win98 читаются теми же 11 px.
- `#/set/<id>/nope` открывает обзор **и нормализует адрес** на `#/set/<id>`: так ссылка
  в строке браузера перестаёт врать. Кнопка «назад» после этого возвращает к прежней
  записи истории, а не к несуществующей вкладке.
- Список наборов показывает состояние без причины простоя — причина осталась на обзоре
  хоста, в строке набора. Дублировать красную строку в двух таблицах не стали.
- Числа `/tool-out` по-прежнему прочерк: поля в API нет (`internal/toolout` знает TTL,
  но наружу его не отдаёт). Подпись под плитками говорит об этом прямым текстом.

## Жалоба владельца: «через гуй настроить ничего нельзя, ничего не сохраняется»

Проверка на чистой установке: `MCPRIG_DATA_DIR=/tmp/opencode/clean-data
MCPRIG_AUTH=off MCPRIG_PORT=9114`, в каталоге только `manager.pid`, панель
открывается на обзоре хоста (`#/`).

**Что воспроизвелось.** Набор создаётся (запись в `registry.json` появляется,
рельс показывает `lab :9115 · stopped`), но панель остаётся на обзоре хоста:
адрес не меняется, вкладки набора скрыты, клик по набору в рейле меняет только
`document.title` (`mcprig — set lab`) — `location.hash` остаётся `#/`, видимая
страница остаётся `#page-host`. С чистой установки попасть в набор нельзя:
вкладок нет, значит нет ни «Add server», ни ключей, ни логов.

**Корень.** `select()` писал адрес и, значит, переключал страницу только когда
панель уже стояла на странице наборов:
`if (st.page === 'sets' && id && (force || location.hash.indexOf('#/set/') === 0))`
(`web/app.js:1976`). Явный выбор — клик в рейле (`web/app.js:4085-4091`,
`select(row.dataset.id, true)`) и создание набора (`web/app.js:4525`,
`select(set.id, true)`) — приходил с `force`, но при `st.page === 'host'` блок
пропускался целиком. Отсюда же второй симптом: при создании набора с обзора
адрес не менялся, а при создании со страницы набора появлялся сразу
`#/set/<id>/servers` — то есть поведение зависело от того, откуда пришли.

**Правка** (`web/app.js:1971-1980`): явный выбор открывает страницу набора сам,
а не только пишет адрес.

```js
if (id && (force || location.hash.indexOf('#/set/') === 0)) {
  if (st.page !== 'sets') { applyPage('sets'); }
  var next = setHash(id, st.tab);
  if (location.hash !== next) { history.pushState(null, '', next); }
}
```

Автовыбор первого набора (`select(ids[0])` без `force`) страницу не трогает,
поэтому `#/` по-прежнему открывается обзором хоста, а `#/sets` — списком.

**Проверка на сборке из ветки** (`MCPRIG_DATA_DIR=/tmp/opencode/nav-data
MCPRIG_AUTH=off MCPRIG_PORT=9117`), playwright:

| Шаг | Ожидание | Факт |
| --- | --- | --- |
| чистый старт `#/` | обзор, 0 вкладок | `#/`, `#page-host`, вкладок 0 |
| создать первый набор | страница набора, вкладки | `#/set/lab`, `#page-sets`, вкладок 6 |
| из `#/` клик по набору в рейле | открыть набор | `#/set/lab`, вкладок 6 |
| из `#/stats/today` клик по рейлу | открыть набор | `#/set/lab`, вкладок 6 |
| загрузка `#/` | обзор, без автоперехода | `#/`, обзор, 0 вкладок |
| `#/sets` | список наборов | `#page-sets`, список, вкладок 0 |
| строка списка → набор → «назад» | набор → список | `#/set/lab` → `#/sets` |

Сквозной сценарий на той же сборке: набор `lab` → сервер `dap`
(`/home/sintez/.local/share/dap-mcp/bin/dap-mcp`, stdio) → «add to set» →
Start → `running`, сервер `Healthy`, 13 инструментов `approved` → ключ `cli`
выдан (`3dbaf40f977a…`) → `initialize` на `http://127.0.0.1:9118/mcp` → 200,
`tools/list` 9 мета-инструментов, `invoke_command({server:"dap",
command_name:"debug_list_sessions"})` → `{"sessions":[]}`. То есть после правки
чистая установка настраивается через панель до работающего MCP-эндпоинта.

**Что при проверке работало и правки не требует:** создание набора (в том числе
с пустым портом — берётся свободный, и с занятым — «порт 9116 занят набором
no-port»), создание и правка сервера (`env`, `cwd`, описание сохраняются и
возвращаются в форму после переоткрытия), привязка сервера к набору, запуск
набора с внятной ошибкой на неразрешимой переменной («переменная GITEA_TOKEN:
источник не найден …; набор lab не запущен»), переменные `#/vars` («value saved
for TEST_VAR · file»), выдача и отзыв ключей, тема и язык (`localStorage`
`mcprig.theme` / `mcprig.palette.win98` / `mcprig.lang` переживают перезагрузку).

**Найденное рядом, не исправлено:** список ключей показывает идентификатор
ключа (`9cdc08cd1c79`), а подпись обещает «первый 8 символов» токена — мелочь
копирайта; `web/codemap.md` отстал от PR #31 по номерам строк (обновлена
только секция экранов, затронутая этой правкой).
