# Приёмка панели 0.6.5: четыре расхождения и их причины

Владелец проверил выпущенный бинарь на своём инстансе (`MCPRIG_DATA_DIR=/tmp/opencode/verify-data`,
порт 9112, `MCPRIG_AUTH=off`, `?mock=1`) и нашёл четыре места, где панель ведёт себя
не так, как обещал отчёт предыдущей полосы (`docs/history/audits/2026-11-17-panel-pages.md`).
Правки — в `web/`, ветка `fix/panel-acceptance`. `CHANGELOG.md`, `CHANGELOG.ru.md` и
`docs/history/index.md` правит тот, кто сводит ветку: нужные строки выписаны в конце.

Проверял по реальному рендеру: свой инстанс (`MCPRIG_DATA_DIR=/tmp/opencode/pages-data`,
порт 9099, `MCPRIG_AUTH=off`) и демо-данные `?mock=1` из `web/mock/*.json`. Ширины
375, 768 и 1280, языки EN и RU, схемы dark и w98 (Win98 поверх своих 10–11 px).

## 1. Неизвестный маршрут открывал последний набор

Причина не в одной строке, а в трёх местах сразу:

- `pageOf()` (`web/app.js`) отдаёт `sets` для любого незнакомого адреса — так и было задумано;
- `route()` приводил панель к адресу только когда в адресе назван набор
  (`if (r.page === 'sets' && r.set)`), поэтому на `#/nonsense` ничего не менялось:
  оставался `st.sel` от прошлого клика;
- `renderChrome()` считал `onSets = st.page === 'sets'` и на любой странице наборов
  показывал шапку набора и вкладки. **Списка наборов в панели не существовало вовсе** —
  списком был только левый рельс, а `#/sets` открывал обзор последнего выбранного набора.
  Это и видел владелец: `#/sets` на скриншоте `design/ui/panel-pages/after-sets-1280-dark-en.png`
  предыдущей полосы — обзор набора `main`, а не список.

Что сделано:

- появилось состояние `st.list` — «страница наборов без набора в адресе»; `route()`
  ставит его из адреса и в этом случае обнуляет `st.sel`;
- в `#page-sets` добавлен блок `#sets-list`: таблица **Set** (имя и `:port`), **State**,
  **Servers**, **Keys** — строка ведёт на `#/set/<id>`; данные те же, что уже приходят
  в `/api/state`, ни одного нового поля бэкенда;
- `renderChrome()` в режиме списка прячет шапку набора, вкладки и **все панели вкладок**
  (`applyTab(null)`), показывает `#sets-list` и рисует его же (`renderSetsList()`);
- `loadState()` в режиме списка не выбирает первый набор автоматически — раньше
  `indexOf(null) === -1` тянул `select(ids[0])` и список немедленно превращался в набор;
- `select()` снимает режим списка и вызывает `renderChrome()`, поэтому шапка и вкладки
  возвращаются вместе с набором;
- крошка в режиме списка называет страницу (`Наборы`), а не прочерк.

Проверено в браузере: `#/nonsense` → список, `#/sets` → список, `#/set/main` → набор,
клик по строке списка кладёт `#/set/main` в историю, «назад» возвращает к списку.

## 2. Заголовок окна не следовал странице

Было: `document.title = st.sel ? t('title.set', {name: st.sel}) : t('title.panel')` —
`st.sel` переживал переход на другую страницу, поэтому `#/` и `#/sets` назывались
`mcprig — set main`, а по-английски ещё и `set` вместо имени набора.

Стало (`setTitle()`, вызывается из `renderChrome()`, `setTab()` и `select()`):

| адрес | заголовок EN | заголовок RU |
| --- | --- | --- |
| `#/` | `mcprig — Overview` | `mcprig — Обзор` |
| `#/sets` | `mcprig — Sets` | `mcprig — Наборы` |
| `#/stats/7d` | `mcprig — Statistics` | `mcprig — Статистика` |
| `#/servers` | `mcprig — All servers` | `mcprig — Все серверы` |
| `#/vars` | `mcprig — Variables` | `mcprig — Переменные` |

Набор называется по имени, а не по `id`.

## 3. Мок отставал от выпуска

`web/mock/state.json` отвечал `version: 0.6.4`, живой `/api/state` — `0.6.5`; подвал
панели показывает именно это поле, так что демо-режим врал о версии. Исправлено на
`0.6.5`. Остальные поля сверены тем же скриптом, что и в прошлый раз
(`/tmp/opencode/mock-parity.py`: собирает все `json:"…"` теги из `internal/` и имена из
map-литералов, затем walk по `web/mock/*.json`): `mock: все поля есть в живых ответах
(257 имён сверено)`. Ключи `reloadErrors`, `failed`, `throttledTools` скрипт пропускает —
их ключи это id наборов, а не поля.

## 4. «Latest calls» на обзоре хоста на 375 px

Вкладку **Calls** набора владелец признал годной и просил не трогать — она и не
тронута: у `#calls-table` прежняя раскладка `data-label`.

Плохо было на обзоре хоста: `#host-calls-table` — настоящая таблица из шести колонок,
на 375 px она сжималась и подписи TIME/SET/SERVER/TOOL/MS/STATUS перемешивались со
значениями. Теперь при ширине ≤ 760 px каждая строка — карточка, запись читается сверху
вниз:

```
11/08, 23:14                              ● ok
main                              socraticode
codebase_search                           329
```

Время (моно, приглушённое) и статус — первая строка; набор и сервер — вторая;
инструмент (моно, переносится) и миллисекунды — третья. Ячейки получают `data-col`
в `renderHostCalls()`, раскладка — в `web/app.css` под `#host-calls-table` (правило
привязано к id этой таблицы, поэтому вкладку **Calls** не задевает). На 768 и 1280
таблица остаётся таблицей: свёртка включается на ≤ 760 px.

## Отклонения и то, что осталось как есть

- **Win98** держит свои 10–11 px и 21–24 px хром — это зафиксированное решение
  предыдущей полосы (пункт 6 в `2026-11-17-panel-fixes.md`): тема воспроизводит систему,
  а не современный интерфейс. Правило «не мельче 12 px / цель ≥ 32 px» выполняется в
  четырёх схемах Default; карточки вызовов в Win98 читаются теми же 11 px.
- `#/set/<id>/nope` открывает обзор **и нормализует адрес** на `#/set/<id>`: так ссылка
  в строке браузера перестаёт врать. Кнопка «назад» после этого возвращает к прежней
  записи истории, а не к несуществующей вкладке.
- Список наборов показывает состояние без причины простоя — причина осталась на обзоре
  хоста, в строке набора. Дублировать красную строку в двух таблицах не стали.
- Числа `/tool-out` по-прежнему прочерк: поля в API нет (`internal/toolout` знает TTL,
  но наружу его не отдаёт). Подпись под плитками говорит об этом прямым текстом.

## Жалоба владельца: «через гуй настроить ничего нельзя, ничего не сохраняется»

Проверка на чистой установке: `MCPRIG_DATA_DIR=/tmp/opencode/clean-data
MCPRIG_AUTH=off MCPRIG_PORT=9114`, в каталоге только `manager.pid`, панель
открывается на обзоре хоста (`#/`).

**Что воспроизвелось.** Набор создаётся (запись в `registry.json` появляется,
рельс показывает `lab :9115 · stopped`), но панель остаётся на обзоре хоста:
адрес не меняется, вкладки набора скрыты, клик по набору в рейле меняет только
`document.title` (`mcprig — set lab`) — `location.hash` остаётся `#/`, видимая
страница остаётся `#page-host`. С чистой установки попасть в набор нельзя:
вкладок нет, значит нет ни «Add server», ни ключей, ни логов.

**Корень.** `select()` писал адрес и, значит, переключал страницу только когда
панель уже стояла на странице наборов:
`if (st.page === 'sets' && id && (force || location.hash.indexOf('#/set/') === 0))`
(`web/app.js:1976`). Явный выбор — клик в рейле (`web/app.js:4085-4091`,
`select(row.dataset.id, true)`) и создание набора (`web/app.js:4525`,
`select(set.id, true)`) — приходил с `force`, но при `st.page === 'host'` блок
пропускался целиком. Отсюда же второй симптом: при создании набора с обзора
адрес не менялся, а при создании со страницы набора появлялся сразу
`#/set/<id>/servers` — то есть поведение зависело от того, откуда пришли.

**Правка** (`web/app.js:1971-1980`): явный выбор открывает страницу набора сам,
а не только пишет адрес.

```js
if (id && (force || location.hash.indexOf('#/set/') === 0)) {
  if (st.page !== 'sets') { applyPage('sets'); }
  var next = setHash(id, st.tab);
  if (location.hash !== next) { history.pushState(null, '', next); }
}
```

Автовыбор первого набора (`select(ids[0])` без `force`) страницу не трогает,
поэтому `#/` по-прежнему открывается обзором хоста, а `#/sets` — списком.

**Проверка на сборке из ветки** (`MCPRIG_DATA_DIR=/tmp/opencode/nav-data
MCPRIG_AUTH=off MCPRIG_PORT=9117`), playwright:

| Шаг | Ожидание | Факт |
| --- | --- | --- |
| чистый старт `#/` | обзор, 0 вкладок | `#/`, `#page-host`, вкладок 0 |
| создать первый набор | страница набора, вкладки | `#/set/lab`, `#page-sets`, вкладок 6 |
| из `#/` клик по набору в рейле | открыть набор | `#/set/lab`, вкладок 6 |
| из `#/stats/today` клик по рейлу | открыть набор | `#/set/lab`, вкладок 6 |
| загрузка `#/` | обзор, без автоперехода | `#/`, обзор, 0 вкладок |
| `#/sets` | список наборов | `#page-sets`, список, вкладок 0 |
| строка списка → набор → «назад» | набор → список | `#/set/lab` → `#/sets` |

Сквозной сценарий на той же сборке: набор `lab` → сервер `dap`
(`/home/sintez/.local/share/dap-mcp/bin/dap-mcp`, stdio) → «add to set» →
Start → `running`, сервер `Healthy`, 13 инструментов `approved` → ключ `cli`
выдан (`3dbaf40f977a…`) → `initialize` на `http://127.0.0.1:9118/mcp` → 200,
`tools/list` 9 мета-инструментов, `invoke_command({server:"dap",
command_name:"debug_list_sessions"})` → `{"sessions":[]}`. То есть после правки
чистая установка настраивается через панель до работающего MCP-эндпоинта.

**Что при проверке работало и правки не требует:** создание набора (в том числе
с пустым портом — берётся свободный, и с занятым — «порт 9116 занят набором
no-port»), создание и правка сервера (`env`, `cwd`, описание сохраняются и
возвращаются в форму после переоткрытия), привязка сервера к набору, запуск
набора с внятной ошибкой на неразрешимой переменной («переменная GITEA_TOKEN:
источник не найден …; набор lab не запущен»), переменные `#/vars` («value saved
for TEST_VAR · file»), выдача и отзыв ключей, тема и язык (`localStorage`
`mcprig.theme` / `mcprig.palette.win98` / `mcprig.lang` переживают перезагрузку).

**Найденное рядом, не исправлено:** список ключей показывает идентификатор
ключа (`9cdc08cd1c79`), а подпись обещает «первый 8 символов» токена — мелочь
копирайта; `web/codemap.md` отстал от PR #31 по номерам строк (обновлена
только секция экранов, затронутая этой правкой).

### Бейдж состояния набора был чёрным

Найдено при просмотре скриншотов: в списке наборов и на обзоре хоста состояние
рисовалось чёрным кружком. Причина — два соглашения об имени класса в одном
месте: `setState()` возвращает `cls: 'ok'|'err'|'warn'`, `badgeState()` —
`'badge-ok'|'badge-err'|'badge-unknown'`, а `paintBadge()` склеивал
`'badge ' + cls`, и для `setState` получался класс `badge ok`, которого в
`web/app.css` нет (там `.badge-ok`, `.badge-err`, `.badge-warn`, `.badge-unknown`).

Правка — одна строка в `paintBadge` (`web/app.js:1741-1746`): префикс `badge-`
добавляется, только если его нет. Проверено на `?mock=1#/sets` (1280, тёмная
тема): `badge badge-ok` → `rgb(67, 196, 139)`, `badge badge-err` →
`rgb(242, 119, 110)`, кружок берёт цвет из `currentColor`.

## Полировка после приёмки

Три косметических дефекта, найденных на живом инстансе (1280×900, тёмная тема,
EN). Правка — в `web/app.css`, плюс одна строка в `web/app.js`. Поведение и
разметка не менялись.

### 1. Колонки `#sets-table` разъезжались

**Было.** Set 301, State 305, Servers 223, Keys 158 при ширине таблицы 988 px
(у владельца 1031 — разница в шрифте). State занимал вчетверо больше своего
содержимого (бейдж ~78 px), между State и Servers — пустой провал, числа
прижаты вправо.

**Причина.** У таблицы авто-раскладка. Заданная `width` у `th` в ней — только
пожелание: лишнее место браузер раздаёт по своему усмотрению, и колонка из
одного слова получает столько же, сколько колонка с названием набора. Одни
`th { width }` ширины не сдвинули ни на пиксель — понадобился `table-layout`.

**Стало** (`web/app.css:534-541`): `#sets-table { table-layout: fixed }` плюс
`th:nth-child(2)` 140 px, `(3)` 110 px, `(4)` 96 px. Замер: Set 642 / State 140
/ Servers 110 / Keys 96. Русские заголовки «Состояние» и «Серверов» в свои
колонки помещаются (`th.scrollWidth === th.clientWidth`).

Мобильный вид не затронут: `#sets-table` — тот же `.rtable`, что у
`#host-calls-table`, на ≤ 760 px строки становятся карточками
(`display: block`), и `table-layout` там ни на что не влияет. Проверено на 375
и 700 px.

### 2. Точка-разделитель висела в конце строки

**Было.** `#f-version` содержал `mcprig 0.6.5 ·`: разделитель лежал внутри
спана версии. На 375 px, когда хвост статусбара не влезал, строка рвалась после
точки, и «обновлено» уезжало вниз без версии, к которой относится.

**Стало.** Точка убрана из текста (`web/app.js:1603`, `renderChrome`), её
рисует CSS: `.statusbar #f-version + span::before { content: '·' }`
(`web/app.css:802`) — точка принадлежит тому, что за ней следует, и переносится
вместе с ним. Сам статусбар стал `flex-wrap: wrap` с `min-height` вместо
`height` (`web/app.css:787-794`), а правая группа неразрывна —
`.statusbar .right { white-space: nowrap; gap: 6px }` (`web/app.css:795-801`),
поэтому время не отрывается от «обновлено».

Проверено на искусственно длинном счётчике при 375: правая группа целиком
уходит на вторую строку, статусбар растёт с 30 до 35 px, висящей точки нет. В
обычном случае строка одна, высота 30 px.

## Приёмка «каждый модуль, каждая кнопка»: что было сломано и как починено

Прогон приёмки на чистой установке (пустой `MCPRIG_DATA_DIR`, `MCPRIG_AUTH=off`,
сборка из рабочего дерева) — 37 шагов, потом обход **каждой видимой кнопки** на
одиннадцати маршрутах при 1280 и 375, в светлой и тёмной схеме, с перехватом
`pageerror`, `console.error`, `requestfailed` и ответов ≥ 400.

Дефекты, найденные этим обходом, и корень каждого:

- **Адрес набора вынимался из DOM на секунду показа «copied».** Кнопка `#copy`
  (`web/index.html:69-77`) — это `button`, а внутри неё живёт `span#endpoint`;
  `copyText()` (`web/app.js:4336-4352`) писала отклик в саму кнопку через
  `btn.textContent`, то есть стирала детей вместе с адресом, и возвращала
  разметку через 1200 мс. Любой `renderChrome()` в эти 1,2 с падал на
  `$('endpoint').textContent` — `TypeError: Cannot set properties of null`.
  Воспроизводилось детерминированно: скопировать адрес, затем сменить язык.
  Починено тем, что отклик пишется в подпись кнопки (`#copy-label`,
  `web/index.html:74`), а возврат берёт строку заново через `data-i18n` — язык
  мог смениться, пока показывался отклик.
- **Удаление открытого набора уводило в соседний набор** (`delSet()`,
  `web/app.js:2754`): после удаления выбирался следующий по рейлу. Читается как
  «не тот набор». Теперь возврат к списку: `location.hash = '#/sets'`.
- **Статистика по прямому адресу пустовала до 15 секунд.** `loadStats()`
  (`web/app.js:3529`) выходит рано, пока `st.sets` пуст: на загрузке
  `#/stats/today` запрос уходил раньше `/api/state`, а следующий — только по
  пятнадцатисекундному тику. Теперь `select()` догружает статистику, когда она
  открыта (`web/app.js:2008`): первый запрос `/api/stats` уходит на 155–170 мс
  после навигации.
- **Фильтры статистики не переживали перезагрузку.** Сервер, инструмент и клиент
  жили только в памяти. Теперь они читаются из `localStorage` при старте
  (`web/app.js:894`) и пишутся при изменении (`:4183`) и при сбросе (`:4194`);
  выбор, которого нет в новых `facets`, по-прежнему снимается загрузкой.
- **Пустая задача в промте не давала отказа**: `buildPrompt()` ставил фокус и
  выходил, `#prompt-err` оставался пустым, кнопка — активной. Теперь видимый
  отказ (`web/app.js:3047`, строка `prompt.taskRequired` в обеих локалях).
- **Подсказка «в наборе нет серверов» была недостижима**: `#prompt-nosrv` лежал
  внутри `#prompt-srv-field`, а именно это поле при нуле серверов и скрывалось
  (`openPrompt()`, `web/app.js:3040-3043`). Подсказка вынесена из поля
  (`web/index.html:955`).

Что осталось открытым и ушло отдельной полосой: диалог лога сервера всегда
показывал «0 lines», потому что `Runtime.ServerLogs`
(`internal/manager/runtime.go:706`) фильтрует лог набора (строки HTTP-доступа),
а stdout/stderr ребёнка живёт только в 4 КБ `stderrTail`
(`internal/downstream/connect.go:207-230`) и до лога не доходит.

Проверки после правок: приёмка — 37/37, обход кнопок — без `pageerror` и без
ответов ≥ 400 (кроме ожидаемых отказов валидации), `scrollWidth === clientWidth`
на 375 для всех маршрутов, консоль пуста.

## Третий проход: CodeQL и узкий экран

Приёмка переехала в репозиторий (`scripts/acceptance/panel.cjs`, 37 шагов,
`ACC_BASE` и `ACC_DAP`), и обход кнопок на живом хосте (`host-sweep2.cjs`, 48
кликов по 6 маршрутам) дефектов не дал.

CodeQL на PR #32 завёл пять алертов в новом коде; закрыто в `546a257`:
`clearServerLogs` проверяет имя набора через `safepath.Name` (`go/path-injection`),
`warn` хвоста сервера и ошибка очистки идут через `safelog.Value`
(`go/log-injection`), отчёт приёмки пишется только по `ACC_OUT` и с правами 0600
(`js/insecure-temporary-file`).

Последний видимый дефект узкого экрана: отклик копирования ужимал кнопку адреса
с 74 до 45 px. Теперь на `≤ 640 px` отклик — знак, а ширина кнопки держится
74 px; подпись помечена `aria-live` ради скринридера (`16fa73b`).

Итог прогонов: приёмка `37/37` — четыре раза на `3c92d16` и дважды на `16fa73b`;
ворота на `3c92d16`: `build`, `vet`, `go test ./... -race -count=1 -p 1`
(17 пакетов), `golangci-lint` (0 issues), `docs-check` (5 из 5), `node --check`.

## Четвёртый проход: ревью старшего разработчика и аудит репозитория

Владелец попросил два разбора в одном формате — «что делает изменение →
Must / Should / Nice → вердикт»: ревью ветки `fix/panel-acceptance` и аудит всего
репозитория. Работали четыре полосы: arbiter (ревью ветки), janitor
(сопровождаемость), paladin (безопасность), hunter (пути отказа).

| Находка | Что сделано |
| --- | --- |
| Must: метка `— запуск —` писалась только в новом файле (`serverlog.go`) | `markStart` вызывается и при каждом `Writer`, и после `Truncate(0)` |
| Must: `clearServerLogs` только в `stopProc` — кнопка Restart после падения стирала улику | чистка перенесена в `startLocked` и только при `restarts == 0`, автоперезапуск дописывает в тот же файл |
| Must: e2e-контракт «стоп стирает лог» разошёлся с кодом | тест проверяет обратное: после `stop` строки на месте, после `start` — свои |
| Should: `X-Forwarded-*` доверялись любому loopback-пиру при заданном секрете | `trustsProxy` сверяет `x-mcp-proxy-secret` в постоянном времени до адреса пира |
| Should: `Runtime` не освобождал кольца, замки и нонсы удалённого набора | `Runtime.Forget(id)` из `apiSetDelete` |
| Should: `.owner` в `/tmp/tool-out` писался через `os.WriteFile` | `O_CREATE|O_EXCL` + `0600` |
| Should: CLI не читал поле `error` журнала сервера | поле в ответе, команда печатает причину |
| Should: `panel_test.go` урезан, потеряны два теста | `TestPanelLogin`, `TestPanelHeadersWithoutSecret` восстановлены |
| Should: нет теста на строгое правило id | `TestAddSetTakesIDAsTyped` |
| Should: причина провала урезана в DOM | полный текст в DOM, обрезка только CSS |
| Should: плитки печатали `0` при неизвестном числе | `null` до данных, прочерк в подписи |
| Should: `${VAR}` разбирался тремя регулярками | одна грамматика `config.EnvRefs` / `config.ExpandEnvRefs` |
| Nice: `Value` вырезал табы из `mcprig logs` | `safelog.Text` сохраняет `\t`, `Value` остаётся строгим |
| Nice: `saveNote` трогал общий `st.busy` | блокируется только кнопка |
| Nice: приёмка глушила таймауты `waitForFunction` | таймаут — провал шага |
| Nice: `portFree` отвечал «порт занят» на `TIME-WAIT` | до пяти попыток с паузой 200 мс |

Отдельно: журнал набора (`GET /api/sets/<id>/logs`) теперь тоже отдаёт `error`,
когда файл есть, но не читается, — раньше это было неотличимо от молчания
набора; вкладка **Logs** печатает причину.

Документация: `docs/en|ru/panel.md` описывают новый контракт хвостов (переживает
остановку, стирается на следующем запуске, метка на каждый запуск, порядок
слияния строк и поле `error`), требование `x-mcp-proxy-secret` для доверия
`X-Forwarded-*`, а `CHANGELOG.md` / `CHANGELOG.ru.md` получили строки под
`[Unreleased]`.
