# Панель: неудачи применения правки больше не выглядят успехом

Две находки финального ревью, обе — про ответы, которые бэкенд уже отдаёт,
а панель не читает. Зона — только `web/` (`app.js` и два файла `web/mock/`):
Go-код менеджера к этому моменту уже клал неудачи в ответ
(`internal/manager/api.go:1085-1114` — `reloadErrors` у `PUT/DELETE /api/env/<NAME>`,
`internal/manager/api.go:1485-1505` — `failed` у `PUT /api/sets/<id>`), поэтому
правки только в клиенте.

`vars.reloadWarn` добавлены в EN и RU (`web/app.js`, блоки `vars.*`).

Демо-данные: `web/mock/env.json` — у `MEMORY_DSN` поле `reloadErrors`
(`{"lab": "набор lab лежит: порт 9108 занят (демо)"}`), его отдаёт ветка

Форму мока для набора переделал: в `web/mock/state.json` поля `failed` нет —
живой `GET /api/state` его не отдаёт, — и ответ `PUT /api/sets/<id>` собирает
сама `mockSend`: вид набора плюс `failed: {"<id>": "причина"}`, как у
`apiSetPut` (`internal/manager/api.go:1485-1505`). Неудачу демо изображает
у набора `lab` (он и в `state.json` лежит с ошибкой запуска), у остальных
ответ чистый.

## Риски

- Формат строки причины — `<id>: <причина>`, как у `srv.reloadWarn`; при
  нескольких наборах в `reloadErrors` они склеиваются через `; `. Для env
  множественная неудача возможна, для `PUT /api/sets/<id>` карта всегда об
  одном наборе.
- Демо изображает неудачу правки набора одним правилом в `mockSend` (`lab`),
  а не полем фикстуры: форма ответа совпадает с живой, но выбор набора
  зашит. Добавить второй «падающий» набор — дописать его id в условие.
