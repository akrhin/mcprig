# Если что-то не работает

Десять отказов, которые действительно случались, в виде симптом → причина → что
сделать. Ничего выдуманного; каждая запись кончается страницей с подробностями.

## 1. Набор не стартует: порт занят

**Симптом.** Панель показывает набор остановленным, либо `POST …/start` отвечает
`порт 9100 занят другим процессом` / `порт 9100 занят набором other`.

**Причина.** Порты 9100–9199 делят наборы, тесты и чужие сервисы на хосте;
выдача портов пропускает те, что уже держит чужой слушатель, а явный `port` в
конфиге проверяется и отвергается.

**Что сделать.** Дать выдаче выбрать порт или взять свободный. `mcprig doctor`
перечисляет чужие слушатели в этом диапазоне — их пропускают намеренно. Тесты и
наборы никогда не должны идти параллельно в одном диапазоне: `go test … -p 1`.

## 2. Один сервер мёртв, остальной набор работает

**Симптом.** `list_servers` отдаёт `healthy: false` с текстом ошибки, а `serve`
стартует с `servers=N` на единицу меньше.

**Причина.** Битая запись проваливается мягко намеренно: одна опечатка не должна
класть весь набор. Типичные тексты: `не удалось определить тип: ни url, ни
command`, `stdio не может иметь url`, `cwd допустим только для stdio`,
`неизвестные поля: …`.

**Что сделать.** Починить одну запись — текст называет поле. Исключение —
пустой `name` сервера или невалидный JSON: они валят загрузку целиком.

## 3. `context deadline exceeded` на сервере с Python SDK

**Симптом.** stdio-сервер отваливается по таймауту на `initialize`, хотя та же
команда руками отвечает быстрее секунды.

**Причина.** go-sdk открывает сессию методом `server/discover` (SEP-2575), а у
сервера на Python `mcp` 1.9.0 такого метода нет: он отбивает запрос и умирает не
ответив — прокси видит только свой 15-секундный дедлайн. Исправлено в v0.3.2:
stdio-сессии идут через `initialize` с ревизией `2025-11-25`, HTTP по-прежнему
через `server/discover`.

**Что сделать.** Обновиться. На старой сборке настройки, которая поможет, нет.

## 4. Клиент подключился, но инструментов не видит

**Симптом.** Список инструментов у клиента пуст, либо каждый запрос отдаёт `401`.

**Причина.** Набор по умолчанию закрыт: нужен bearer-ключ, а
`allowAnonymous: false` — значение по умолчанию. Бывает и обратная ошибка:
*открытый* набор отвергает любой присланный `Authorization`, потому что
сравнивать его не с чем.

**Что сделать.** Взять фрагмент, который печатает
`mcprig init --client … --set <id>`, и ключ рядом с ним; у открытого набора
заголовок надо убрать, а не придумать.

## 5. `invoke_command` отвечает «лишние ключи»

**Симптом.** Вызов падает с ошибкой про неизвестный инструмент или лишние ключи,
хотя инструмент есть.

**Причина.** Имя инструмента идёт в `command_name`. Поля `command` у
`invoke_command` нет — оно из `servers.json`.

**Что сделать.** `{"server": "…", "command_name": "…", "parameters": {…}}`.
Схему параметров показывает `describe_commands`.

## 6. OAuth: порт приёма кода занят

**Симптом.** `oauth: занять порт 127.0.0.1:8947 для приёма кода: … (занят?
смените callbackPort в настройках)`.

**Причина.** Loopback-приёмник по умолчанию берёт 8947, и два набора,
аутентифицирующихся одновременно, или что-то ещё на этом порту, сталкиваются.

**Что сделать.** Дать набору свой `oauth.callbackPort`. Токены лежат в каталоге
состояния набора и переживают перезапуск, поэтому браузер нужен один раз, а не
на каждом старте.

## 7. Песочница отказывается запускать сервер

**Симптом.** `sandbox unavailable: …`, либо сервер падает с `sandbox: путь
"…" не существует`, а в контейнере bwrap печатает
`Can't mount proc on /proc: Operation not permitted`.

**Причина.** bubblewrap нужны непривилегированные user namespaces. Профиль
seccomp у Docker по умолчанию их запрещает; rootless-демон запрещает больше,
чем seccomp. Умолчание `onUnavailable: deny` — fail-closed намеренно, и сервер с
тегом `untrusted` другого значения не принимает.

**Что сделать.** Запустить контейнер с `--security-opt seccomp=unconfined`; на
rootless-демоне из измеренного работал только `--privileged`. Для сервера без
тега `untrusted` можно `onUnavailable: warn` — он пойдёт без изоляции с
предупреждением в логе набора.

## 8. В контейнере нет `npx` или `uvx`

**Симптом.** `npx: executable file not found in $PATH`, либо сервер умирает
сразу после старта; бывает и `prlimit не найден в PATH`.

**Причина.** В образе `slim` есть бинарник, CA-корни, `bwrap` и `prlimit` — но
нет node и uv. `prlimit` обязан быть в `PATH`: песочница монтирует его по
абсолютному пути.

**Что сделать.** Для серверов на `npx`/`uvx` брать образ `full`. Оба образа несут
`util-linux`; в своей сборке его надо поставить.

## 9. Панель отвечает 403 или недоступна с другой машины

**Симптом.** Запись падает с `403 "нужен заголовок Origin"`; за реверс-прокси
отвергается `https`-Origin; или панель не принимает соединения из локальной сети.

**Причина.** Три разных правила: запись с cookie обязана нести `Origin` (браузер
его шлёт, скрипт часто нет); `Origin` сравнивается целиком — схема, хост и порт,
поэтому за TLS запрос выглядит как обычный http, пока прокси не скажет обратное;
а незаданный `MCPRIG_HOST` означает только loopback.

**Что сделать.** Слать `Origin`; в прокси выставить `X-Forwarded-Proto: https`
(и `X-Forwarded-Host`, плюс `X-Forwarded-Port`, если публичный порт другой);
задать `MCPRIG_HOST` и внести хост в `MCPRIG_ALLOWED_HOSTS` — этот список
называет саму панель, а не источники, которым можно к ней ходить. Своего TLS у
панели нет: держите её за прокси.

## 10. Ответ пришёл обрезанным

**Симптом.** Результат кончается строкой `[обрезано: 32768 из 149873 байт,
полный ответ — /…/tool-out/1f3c9a2b7d4e5f60.txt]`.

**Причина.** `maxBytes` по умолчанию 32768 (у `invoke_command` и `invoke_many`;
`list_commands` и `describe_commands` без него ничего не режут), поэтому
большой ответ режется, а полный пишется в `tool-out/`.

**Что сделать.** Прочитать файл из маркера (живёт 24 часа, каталог ограничен
256 МиБ) или передать больший `maxBytes` — до 1048576.
