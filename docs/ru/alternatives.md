# Альтернативы и ограничения

Здесь сказано, с чем mcprig сравнивают, что умеет каждая альтернатива и где
mcprig слабее. Всё про чужие продукты взято из их README и документации —
живьём ничего не запускалось. «Последняя активность» — дата `pushed_at` из
GitHub API на 2026-11-16, а не дата релиза; перед тем как повторять таблицу,
проверьте её заново.

Схемы: [зачем один эндпоинт](../diagrams/mcprig.why.ru.html) и
[что умеет mcprig](../diagrams/mcprig.capabilities.ru.html).

## Совсем без прокси

Каждый клиент прописывает каждый сервер сам: N серверов — это N записей в
конфиге каждого клиента, N каталогов инструментов в контексте каждой сессии,
ключи размазаны по клиентам, нет общих правил, нет общего журнала вызовов.

Это не соломенное чучело: у Claude Desktop, VS Code, Cursor и opencode есть
свои менеджеры серверов с включением и проверкой здоровья. Чего у них нет —
одного места для авторизации, политики и наблюдаемости сразу по всем
клиентам. Эту дыру mcprig и закрывает — ценой ещё одного процесса на набор.

## Что есть у mcprig

- Один статический бинарник на Go; ни рантайма, ни базы, ни compose-файла.
- Набор — отдельный процесс со своим портом и своим Bearer-ключом; панель —
  только управление, MCP-трафик она не несёт. Падение одного набора не
  останавливает остальные.
- Девять мета-инструментов вместо каталога: пять работают с серверами
  (`list_servers`, `list_commands`, `describe_commands`, `invoke_command`,
  `invoke_many`), четыре обслуживают ресурсы и промты. Инструмент апстрима
  клиенту не показывается.
- Даунстримы stdio и HTTP; OAuth с PKCE на 401.
- До восьми действующих ключей на набор с отзывом по одному, профили ключа
  сужают `allow`/`deny`, лимиты на вызывающего и на `server/tool`, запреты с
  сообщением.
- Песочница bubblewrap для stdio-серверов: монтирования только для чтения или
  на запись, tmpfs, `RLIMIT_AS`/`NPROC`/`FSIZE` через prlimit; недоверенный
  сервер без песочницы не запускается.
- Панель: наборы, все серверы, переменные, ключи, живые вызовы, статистика с
  p50/p95, готовый промт со схемами инструментов, импорт и экспорт реестра.
- Статистика вызовов живёт в процессе набора: кольцо на 512 вызовов и выборка
  на 256 сэмплов, точные процентили за последние семь дней.

## Где mcprig слабее

| ограничение | подробность |
| --- | --- |
| один оператор | один пароль панели, ролей и отдельных учётных записей нет; режимы — none, password, proxy и both |
| русский текст внутри | справка CLI, диагностика и строки журнала в этой сборке по-русски |
| `X-MCPRig-Caller` | обычный заголовок: клиент, который его ставит, скрывает свои вызовы от статистики |
| охват песочницы | CPU, память всего дерева процессов и сетевой выход не ограничены; `allow` — всё или ничего |
| нет типизированного API | схему инструмента клиент не видит, пока не позовёт `describe_commands` |

Полный список долгов с приоритетами — в
[ревью от 2026-11-15](../history/audits/2026-11-15-review-v0.5.1.md).
