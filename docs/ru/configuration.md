Файл документирует `servers.json`: каждое поле, которое читает прокси, обе формы
`command`, ссылки на секреты и что происходит с битой записью.

# Конфигурация

Набор настраивается одним `servers.json`. Формат общий с lazy-mcp и читается как
есть: без миграции, без обёртки.

```json
{
  "servers": [
    {
      "name": "fs",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/srv/docs"],
      "env": {"LOG_LEVEL": "warn"},
      "tags": ["files"]
    },
    {
      "name": "serena",
      "url": "http://127.0.0.1:8899/mcp",
      "headers": {"Authorization": "Bearer ${SERENA_TOKEN}"}
    }
  ],
  "transport": {
    "type": "http",
    "host": "127.0.0.1",
    "port": 9100,
    "path": "/mcp",
    "authToken": "{file:/home/me/.config/mcprig/demo.token}",
    "allowedHosts": ["127.0.0.1", "localhost"]
  },
  "requestTimeout": 120000
}
```

## Верхний уровень

| поле | тип | по умолчанию | значение |
| --- | --- | --- | --- |
| `servers` | массив | обязательно | нижестоящие серверы, см. ниже |
| `transport` | объект | обязательно для `serve` | слушатель, который выставляет набор |
| `healthMonitor` | `{interval, timeout}` в мс | | принимается для совместимости с lazy-mcp; Go-прокси его не читает |
| `requestTimeout` | int, мс | `0` (без ограничения) | бюджет на один `invoke_command`; по истечении вызов возвращает `таймаут вызова <N> мс` |
| `permissions` | объект | разрешить всё | глобальный блок allow/deny |
| `oauth` | объект | | настройки OAuth по умолчанию для набора, перекрываются на сервере |

`healthMonitor` пишет панель (`interval: 60000`, `timeout: 120000`), чтобы файл
оставался побайтово совместимым с lazy-mcp, но здоровьем в mcprig управляет
кэш на 15 с, описанный в [architecture.md](architecture.md#здоровье).

## Серверы

| поле | тип | по умолчанию | значение |
| --- | --- | --- | --- |
| `name` | строка | обязательно | имя сервера для мета-инструментов; дубли имён получают `_configError: дубль имени` |
| `description` | строка | пусто | показывается в `list_servers` и ищется `filter` |
| `transport` | `stdio` / `http` | выводится | выводится из `url` или `command`, когда отсутствует |
| `command` | массив или строка | | stdio-команда; см. обе формы ниже |
| `args` | массив | пусто | аргументы, добавляемые к `command` в строковой форме (legacy) |
| `cwd` | строка | пусто | рабочий каталог; только stdio, обязан быть абсолютным; в песочнице монтируется только для чтения |
| `env` | объект строк | пусто | дополнительное окружение для stdio-процесса |
| `envAllow` | массив строк | пусто | переменные хоста, которые дополнительно уходят stdio-процессу сверх фиксированной базы (`PATH`, `HOME`, `LANG`, `TZ`, `TMPDIR`, `LC_*`, `XDG_*`, `SSL_*`, `NODE_EXTRA_CA_CERTS`); остальное окружение хоста до него не доходит |
| `url` | строка | | HTTP-точка; только http |
| `headers` | объект строк | пусто | дополнительные заголовки для каждого HTTP-запроса |
| `tags` | массив строк | пусто | метки для `list_servers` и `filter` |
| `sandbox` | объект | нет — без изоляции | блок bubblewrap для stdio-сервера, см. ниже. Сервер с тегом `untrusted` обязан его иметь: без него загрузчик оставляет его в списке нездоровым (`_configError`), а API панели отвергает такую запись с 400 |
| `enabled` | bool | `true` | выключенные серверы показываются в списке, но никогда не подключаются |
| `permissions` | объект | | блок allow/deny для сервера |
| `oauth` | объект | | настройки OAuth для сервера |
| `_configError` | строка | | пишет загрузчик, никогда не пользователь |

### Песочница

Блок `sandbox` запускает stdio-сервер под `bwrap`: своё дерево монтирования,
корень только для чтения (`--remount-ro /`), нет `/home`, нет сети хоста, нет
`/proc/1/root`, а лимиты `prlimit` ставятся внутри пространства имён.

Включить — просто добавить блок: `"sandbox": {}` уже значит `mode: bwrap` со
всеми умолчаниями. Сервер без блока не изолирован вообще. Сервер с тегом
`untrusted` обязан иметь блок **и** сохранять `onUnavailable: deny`:
`{"sandbox": {"mode": "none"}}` у untrusted отвергается с
`тег untrusted требует sandbox: сервер без изоляции не стартует`.

| поле | тип | по умолчанию | значение |
| --- | --- | --- | --- |
| `mode` | `bwrap` / `none` | `bwrap` | `none` выключает изоляцию для этого сервера; от блока остаётся предупреждение |
| `onUnavailable` | `deny` / `warn` / `allow` | `deny` | что делать, если bubblewrap не стартует: отказать серверу (fail-closed), запустить ничем не ограниченным и написать предупреждение в лог набора или запустить молча. Сервер с тегом `untrusted` принимает только `deny` |
| `ro` | массив абсолютных путей | `/usr /bin /lib /lib64 /etc/ssl /etc/resolv.conf /etc/passwd /etc/group` | монтируются только для чтения. Явный список заменяет умолчания, и разрешён любой абсолютный путь — в том числе под `/home`. Пропускаются только отсутствующие *умолчания*; заданный вами путь обязан существовать, и это проверяется при старте сервера, а не при загрузке конфига. Монтирования идут от родителя к ребёнку, поэтому `rw` на подкаталоге внутри `ro`-корня работает, а наоборот — молча остаётся только чтение |
| `rw` | массив абсолютных путей | пусто | монтируются на запись; на одном пути сильнее `ro` |
| `network` | `none` / `allow` | `none` | `allow` оставляет сетевое пространство имён хоста; списка разрешённых хостов нет |
| `memoryMb` | int | `2048` | `RLIMIT_AS` — виртуальная память, не RSS. Go и node требуют не меньше 2048; под 512 не стартует ни один |
| `pids` | int | `256` | `RLIMIT_NPROC`, стоп fork-бомбе |
| `tmpMb` | int | `128` | размер tmpfs `/tmp` **и** `RLIMIT_FSIZE`: самый большой файл, который сервер может записать где угодно, в том числе в `rw`-каталоге. Кэш или база sqlite крупнее падают с `EFBIG` |
| `timeoutSec` | int | `30` | потолок одного вызова инструмента, пока `mode: bwrap` и значение положительное. Действует и тогда, когда изоляция *не* применилась (`warn`/`allow`): вызов обрывается с `таймаут 30s (sandbox)`, сессия сбрасывается |

Ноль означает умолчание: `memoryMb: 0`, `pids: 0`, `tmpMb: 0` и `timeoutSec: 0`
заменяются на 2048 / 256 / 128 / 30, то есть лимит выключить нельзя; отрицательное
значение — ошибка конфига. Неизвестные ключи внутри блока отвергаются, и блок
отбрасывается целиком: сервер остаётся в списке с `sandbox: неизвестные поля: …`
и никогда не стартует. `sandbox` у `http`-сервера — `sandbox допустим только
для stdio`.

```json
{"name": "unknown", "command": ["npx", "-y", "some-mcp@1.2.3"], "tags": ["untrusted"],
 "sandbox": {"network": "none", "memoryMb": 2048}}
```

Явный `ro` заменяет умолчания, но `/lib`, `/lib64`, `/usr/lib` и `/usr/lib64`
при включённых лимитах всё равно монтируются для загрузчика, вместе с ними
монтируется `prlimit` — так что падение из-за «нет библиотеки» маловероятно.
Пропадают на самом деле `/usr` (сам бинарь), `/etc/ssl` и `/etc/resolv.conf`
(TLS и DNS). Рантайм вне `/usr` — node из пользовательского префикса, например, —
надо перечислить в `ro` вместе с нужными ему умолчаниями; `npx` и `uv` пишут
кэши под `$HOME`, поэтому им нужен ещё и `rw` на `~/.npm` или `~/.cache/uv`.

Чего песочница **не** ограничивает: CPU, память всего поддерева (`RLIMIT_AS`
считает один процесс, а node плодит детей) и исходящую сеть — `allow` это «всё
или ничего». Ядро общее, поэтому это изоляция от файловой системы и сетевого
пространства имён хоста, а не виртуальная машина.

Сообщения, которые можно встретить:
`sandbox unavailable: <причина>` (bubblewrap отсутствует или userns запрещён, а
стоит `deny`), `sandbox: путь "…" не существует`, `sandbox: cwd "…" должен быть
абсолютным`, `sandbox: неизвестные поля: …`.

### Обе формы command

```json
{"name": "a", "command": ["npx", "-y", "some-mcp@1.2.3"]}
```

```json
{"name": "b", "command": "npx", "args": ["-y", "some-mcp@1.2.3"]}
```

Обе дают один и тот же argv. Строковый `command` **не** делится по пробелам;
аргументы берутся только из `args`.

### Вывод транспорта и ошибки

| вход | результат |
| --- | --- |
| только `url` | `http` |
| только `command` | `stdio` |
| ни то, ни другое | `_configError: не удалось определить тип: ни url, ни command` |
| `stdio` с `url` | `_configError: stdio не может иметь url` |
| `http` с `command` | `_configError: http не может иметь command` |
| `cwd` у http-сервера | `_configError: cwd допустим только для stdio` |
| неизвестный `transport` | `_configError: неизвестный transport "…"` |

Сервер с пустым `name` валит всю загрузку (`сервер #N без имени`); любой другой
дефект мягко привязывается к этому серверу. Плохой JSON тоже валит загрузку.

### Мягкий отказ

Битый сервер сохраняет свой `_configError`, показывается в `list_servers` как
`healthy: false` с текстом ошибки и исключается из счётчика `servers=N` у
`serve`. Остальной набор работает. Это намеренно: одна опечатка в одной записи
не должна останавливать все остальные серверы.

## Секреты

Две формы ссылок раскрываются при загрузке — в значениях `env`, в значениях
`headers` и в `transport.authToken`:

| форма | источник | правила |
| --- | --- | --- |
| `${VAR}` | окружение процесса | имя должно соответствовать `[A-Za-z_][A-Za-z0-9_]*`; незаданная переменная — ошибка |
| `{file:/absolute/path}` | содержимое файла | путь должен быть абсолютным; один завершающий `\n` или `\r\n` срезается |

```json
{
  "env": {"DB_PASSWORD": "{file:/run/secrets/db_password}"},
  "headers": {"Authorization": "Bearer ${SERENA_TOKEN}"}
}
```

Неудачная ссылка становится `_configError` этого сервера
(`env.DB_PASSWORD: {file:relative}: нужен абсолютный путь`,
`headers.Authorization: переменная SERENA_TOKEN не задана`). Ссылки в `command`,
`url` и `cwd` не раскрываются.

Когда панель материализует набор, `${VAR}` остаётся в файле; процесс набора
раскрывает её из своего окружения, которое включает цепочку секретов менеджера
(OpenBao → `env.json` → окружение процесса; `MCPRIG_*`, `BAO_*` и `OPENBAO_*`
зарезервированы и никогда не передаются нижестоящему серверу).

## transport

| поле | по умолчанию | значение |
| --- | --- | --- |
| `type` | | принимается для совместимости; слушатель всегда HTTP |
| `host` | `127.0.0.1` в `serve` | адрес привязки |
| `port` | `9100` в `serve` | порт привязки; менеджер выделяет 9100–9199 |
| `path` | `/mcp` | путь точки; должен начинаться с `/` |
| `authToken` | | bearer-токен; пустой отказывается стартовать, если не `allowAnonymous` |
| `allowAnonymous` | `false` | открытый набор: заголовок `Authorization` не разрешён |
| `allowedHosts` | loopback | список разрешённых `Host` и `Origin` |

`allowAnonymous` не делает неверный токен допустимым: запрос, который передаёт
`Authorization`, всё равно должен совпасть с `authToken`, а у открытого набора
токена нет, поэтому любой переданный токен получает 401. Клиенты открытого
набора должны опускать заголовок.

Пустой `allowedHosts` означает `127.0.0.1`, `localhost`, `::1`. `"*"` отключает
проверку и пишет предупреждение в лог. Тот же список проверяет `Origin`, когда
заголовок присутствует.

## permissions

```json
{
  "permissions": {
    "default": "allow",
    "rules": [
      {"server": "db", "pattern": "drop_*", "action": "deny", "message": "no destructive SQL"}
    ]
  }
}
```

| поле | значение |
| --- | --- |
| `default` | `allow` или `deny`; неверное значение отключает блок |
| `rules[].pattern` | глоб по имени инструмента; `*` — любая последовательность, `?` — один символ, сравнение без учёта регистра |
| `rules[].server` | глоб по имени сервера; допустим только в глобальном блоке, по умолчанию `*` |
| `rules[].action` | `allow` или `deny`; `ask` не реализован |
| `rules[].message` | текст, показываемый при запрете правила |

Порядок разрешения: побеждает первое непустое, а внутри уровня — **последнее**
подходящее правило:

1. правила сервера;
2. глобальные правила;
3. `default` сервера;
4. глобальный `default`;
5. неявное разрешение.

Запрет — это результат инструмента с `isError: true`, текстом
`🚫 Blocked by mcprig policy: <message>` и `_meta.lazyMcpPolicy: "blocked"`.
Проверка идёт до подключения нижестоящего сервера. Неверный глобальный блок
отбрасывается (разрешено всё); неверный блок сервера становится `_configError`
этого сервера.

## oauth

Клиентский поток authorization-code стартует, только когда сервер отвечает 401
или 403. Пустой блок допустим.

| поле | по умолчанию | значение |
| --- | --- | --- |
| `disabled` | `false` | выключить поток для этого сервера |
| `callbackPort` | `8947` | loopback-порт слушателя редиректа |
| `redirectUrl` | `http://127.0.0.1:<callbackPort>/callback` | зарегистрированный redirect URI |
| `clientId` | | предварительно зарегистрированный клиент |
| `clientSecret` | | только вместе с `clientId`; секрет без идентификатора — ошибка |
| `scopes` | | запрашиваемые scopes |

Блок сервера накладывается на блок набора; незаданные поля откатываются к
значению набора, затем к дефолту. Динамическую регистрацию клиентов, PKCE, обмен
кода и обновление делает MCP SDK. Токены хранятся в `<data dir>/oauth.json`.
