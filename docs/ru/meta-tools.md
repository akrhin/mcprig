Файл документирует мета-инструменты, которые видит клиент, с точными формами
ответов и текстами ошибок.

# Мета-инструменты

Набор выставляет пять инструментов MCP. Нижестоящие инструменты клиенту
не показываются; до них доходят через `invoke_command`.

| инструмент | назначение |
| --- | --- |
| `list_servers` | инвентарь со здоровьем и тегами |
| `list_commands` | имена инструментов одного или нескольких серверов |
| `describe_commands` | входные схемы названных инструментов |
| `invoke_command` | вызвать один нижестоящий инструмент |
| `invoke_many` | вызвать до 8 независимых инструментов одним запросом |

Каждая ошибка ниже возвращается обычным результатом инструмента с
`isError: true` и одним текстовым элементом, текст которого начинается с
`Error: `. Сам вызов MCP при этом не падает.

## list_servers

Вход: `{"filter": "code"}` (`filter` необязателен). Фильтр сравнивается без
учёта регистра с именем, описанием и тегами **до** любого подключения:
отфильтрованный сервер никогда не опрашивается.

```json
{
  "servers": [
    {
      "name": "echo",
      "type": "stdio",
      "enabled": true,
      "healthy": true,
      "tags": ["fixture"]
    }
  ],
  "version": "dev",
  "pid": 666441
}
```

| поле | значение |
| --- | --- |
| `name` | имя сервера |
| `description` | есть, когда в конфигурации задано |
| `type` | `stdio` или `remote` |
| `enabled` | из конфигурации; выключенный сервер не опрашивается и показывается как `healthy: true` |
| `healthy` | результат опроса; `false` при битой конфигурации или неудачном подключении. Проба, не дождавшаяся свободного слота, отдаётся `true` и не кэшируется — смотри `unknown` |
| `unknown` | `true`, когда проба не началась (не было свободного слота): `healthy: true` тут значит «не больной», а не «проверен» |
| `error` | текст ошибки опроса, есть при `healthy: false` |
| `isolation` | `bwrap`, когда песочница применена; `без изоляции: <причина>`, когда запрошена, но bubblewrap не стартовал (`onUnavailable: warn`/`allow`); `нет: конфиг отвергнут`, когда у записи есть `_configError`; поля нет только у валидного сервера без блока `sandbox` |
| `tags` | из конфигурации, когда заданы |
| `version` | версия сборки прокси |
| `pid` | pid процесса прокси |

Опросы здоровья идут параллельно, не больше 8 одновременно, с таймаутом 15 с и
кэшем на 15 с, который запоминает и неудачи.

## list_commands

Вход — одна из двух форм:

| вход | выход |
| --- | --- |
| `{"server": "alpha"}` | массив инструментов |
| `{"servers": ["alpha", "beta"]}` | объект с ключами по имени сервера, каждое значение — массив; у упавшего сервера — `{"error": "…"}` |
| `{"prefix": "se"}` | с любой из форм выше: оставить только имена, начинающиеся с префикса (без учёта регистра); без совпадений — `[]` |
| `{"namesOnly": true}` | с любой из форм выше: только имена — массив строк или массивы по серверам. У большого сервера сотни инструментов и десятки КБ каталога; имена стоят примерно шестую часть, а схему одного инструмента даёт `describe_commands` |
| `{"maxBytes": 4096}` | с любой из форм выше: потолок ответа, предел 1048576. В отличие от `invoke_command` и `invoke_many`, у вызовов каталога **умолчания нет**: без поля или с `0` приходит весь каталог; сверх явного потолка ответ уходит в файл, а маркер говорит, сколько пришло |
| оба | `Error: укажи server или servers, не оба` |
| ни одного | `Error: нужен параметр server или servers` |

`prefix` фильтрует уже прочитанный список при отдаче, поэтому кэш схем не
трогается: следующий вызов без префикса видит все инструменты.

С `servers` один `requestTimeout` ограничивает весь вызов, а не каждый сервер.
Серверы опрашиваются параллельно, по восемь зараз.

`{"refresh": true}` (у `list_commands` и `describe_commands`) выбрасывает
кэш списка инструментов и спрашивает серверы заново. Иначе кэш живёт столько же,
сколько соединение: набор сам сбрасывает его, когда нижестоящий сервер присылает
`notifications/tools/list_changed`, поэтому инструмент, появившийся на живом
соединении, виден со следующего вызова без `refresh`.

```json
[
  {
    "server": "echo",
    "name": "echo",
    "command": "echo",
    "description": "Echo the given text back."
  }
]
```

`name` — каноническое поле; `command` повторяет его для клиентов, написанных под
старую форму. `description` есть, когда сервер его предоставляет. Пагинация
проводится до конца, с потолком 20 страниц.

Один упавший сервер не скрывает остальные: его значение — `{"error": "…"}`,
а ошибку инструмент возвращает, только если не ответил ни один.

## describe_commands

Вход: `{"server": "echo", "command_names": ["echo", "nope"]}`; оба поля
обязательны.

```json
{
  "commands": [
    {
      "name": "echo",
      "description": "Echo the given text back.",
      "inputSchema": {
        "type": "object",
        "properties": {"text": {"type": "string"}},
        "required": ["text"]
      }
    }
  ],
  "missing": ["nope"]
}
```

`missing` присутствует всегда и перечисляет имена, которых сервер не
выставляет; они не валят вызов. `outputSchema` появляется, когда нижестоящий
инструмент его объявляет. `maxBytes` действует и здесь и, как у
`list_commands`, только когда задан: пачка схем сверх потолка уходит в файл с
тем же маркером обрезки.

## invoke_command

Вход:

```json
{
  "server": "echo",
  "command_name": "echo",
  "parameters": {"text": "hello"}
}
```

| поле | значение |
| --- | --- |
| `server` | обязательно |
| `command_name` | одно из `command_name` или его синоним `command` (ниже) |
| `command` | синоним `command_name`; `list_commands` отдаёт имя именно в поле `command`, поэтому годится любой из ключей. Оба с разными значениями — ошибка. Клиент видит схему при старте сессии, поэтому после обновления ему нужно перечитать `tools/list` (или начать новую сессию), иначе старый `required: command_name` перебьёт `anyOf` |
| `parameters` | необязательный объект; `null` и пустая строка означают `{}` |
| `maxBytes` | необязательный потолок ответа в байтах; по умолчанию 32768, не больше 1048576; `0` означает умолчание. Исключение — инструменты каталога `list_commands` и `describe_commands`: они ничего не режут, пока `maxBytes` не задан |

Аргументы нижестоящего инструмента кладутся **внутрь** `parameters`. Любой
другой ключ верхнего уровня — ошибка, поэтому вызов не может молча уйти с
пустыми аргументами:

```text
Error: лишние ключи: path — допустимые: server, command_name, command, parameters, maxBytes; аргументы инструмента кладутся в parameters
```

Неверный тип JSON называется ключом и видом, без Go-типов:
`Error: ключ server: ожидался тип «строка», получен тип «число»`. Префикс
`аргументы:` появляется только тогда, когда ошибка типа не привязана к
именованному ключу — неизвестное или неверной формы поле верхнего уровня,
например `Error: аргументы: ожидался тип «объект», получен тип «строка»`.

Результат нижестоящего сервера возвращается как есть: `content`,
`structuredContent` и `isError` сохраняются. Если соединение падает до первого
байта ответа (`ErrConnectionClosed`, `io.EOF`, сетевая ошибка), прокси один раз
переподключается, ждёт 250 мс и повторяет вызов. Если ответ уже начал приходить
или инструмент вернул `isError`, повтора нет — результат отдаётся как есть,
чтобы не выполнить side effect дважды. `list_commands` и `describe_commands`
не повторяются: у них свои таймауты. `requestTimeout`, когда задан, применяется
к одному вызову.

Ответ длиннее `maxBytes` режется по границе UTF-8; возвращённый текст
заканчивается маркером с размерами и путём к файлу с полным ответом:

```text
…обрезанный текст
[обрезано: 32768 из 149873 байт, полный ответ — /tmp/mcprig-data/tool-out/1f3c9a2b7d4e5f60.txt]
```

Полный ответ пишется с правами `0600` в
`${MCPRIG_DATA_DIR:-$TMPDIR}/tool-out/<случайное>.txt`; каталог создаётся при
первом использовании. Если ответ нёс `structuredContent`, к маркеру добавляется
строка `[structuredContent не влезает в maxBytes: полный ответ в файле]`:
структура в текстовый срез не попадает, и клиенту со structured-смыслом иначе
нечего читать. Ответ в пределах лимита возвращается как есть — без
файла и маркера. Нечисловой или отрицательный `maxBytes`, как и значение
больше 1048576, — ошибка, как любой другой неверный аргумент.

## invoke_many

Вход: `{"calls": [{"server": "echo", "command_name": "echo", "parameters": {"text": "a"}}, …], "maxBytes": 4096}`

| поле | значение |
| --- | --- |
| `calls` | обязателен; от 1 до 8 вызовов, каждый — как один вызов `invoke_command` |
| `maxBytes` | необязательный предел на **каждый** ответ; умолчание и ограничения те же, что у `invoke_command` |

Вызовы идут параллельно. К одному нижестоящему серверу одновременно не больше
4 вызовов (восемь зараз роняли батч), всего — не больше 8. Один
`requestTimeout` ограничивает весь веер, а не каждый вызов.

Ответ — массив, по элементу на вызов, **в порядке `calls`**, а не в порядке
завершения:

```json
[
  {"ok": true, "server": "echo", "command_name": "echo", "result": "echo:{\"text\":\"a\"}", "ms": 12},
  {"ok": false, "server": "nope", "command_name": "x", "error": "неизвестный сервер \"nope\"", "ms": 0}
]
```

`result` — то же, что вернул бы `invoke_command`: текст одиночного текстового
элемента, иначе весь объект результата, усечённый по `maxBytes`. Упавший вызов —
неизвестный или выключенный сервер, запрет правами, ошибка транспорта, таймаут
или результат нижестоящего сервера с `isError: true` — остаётся на своём месте с
`ok: false` и `error`; остальные вызовы это не затрагивает. У отказа правами
`result` несёт тот же ответ, что отдал бы `invoke_command`: маркер
`🚫 Blocked by mcprig policy: …` в `content` и `_meta.lazyMcpPolicy: "blocked"`.

Невалидный вход валит весь запрос с `isError: true`, и ничего не выполняется:
ноль вызовов, больше 8, лишний ключ внутри вызова, нет `server` или
`command_name` (либо его синонима `command`), `parameters` не объект или плохой
`maxBytes`.

## Маскировка секретов

До того как ответ попадёт в счётчики или в `tool-out`, его текстовое содержимое
чистится от секретов самого сервера: значения его `env` и `headers`, в именах
которых есть `key`, `token`, `secret`, `pass`, `auth` или `credential`,
заменяются на `***`. Ведущий `Bearer ` срезается, значение короче 8 символов не
трогается. `structuredContent` не переписывается — это сломало бы клиентов,
которые его читают. Причина: апстрим повторяет ключ в теле ошибки (tavily
присылает `api_key` в validation details), и этот текст иначе попадал бы в
контекст модели.

## Разрешения

Блок allow/deny проверяется до подключения сервера; см.
[configuration.md](configuration.md#permissions). Запрещённый вызов возвращает:

```json
{
  "isError": true,
  "content": [{"type": "text", "text": "🚫 Blocked by mcprig policy: no destructive SQL"}],
  "_meta": {"lazyMcpPolicy": "blocked"}
}
```

Маркер `_meta.lazyMcpPolicy` — то, что ищут хуки хоста.

## Счётчики

Каждый завершённый `invoke_command` — и каждый вызов внутри `invoke_many` —
считается в процессе набора: по клиенту, по серверу и по инструменту, с p50/p95
и кольцом последних вызовов. Результат нижестоящего сервера с `isError: true`
считается провалом. Панель читает это через `GET /stats`; в stdio-режиме те же
счётчики и история пишутся в `$MCPRIG_DATA_DIR/stdio/stats/`, каждый вызов
помечен `stdio` — панели над процессом просто нет.

Метка клиента берётся из `_meta["io.modelcontextprotocol/clientInfo"]` того
запроса, который считается, — это per-request client info из SEP-2575. Формат —
`имя/версия` (`opencode/2.2.6`) или одно `имя`, если версии нет (`mcprig`). Для
stateless HTTP это и нужно: рукопожатия `initialize` там нет, метка едет с
каждым запросом, а не с сессией. Если в `_meta` client info нет, метка падает на
транспорт: подпись ключа, если ключ подписан (`PATCH /api/sets/<id>/keys/<keyID>`),
иначе `key:<6 hex от хеша токена>/<product token из User-Agent>` для набора с
ключом, один `User-Agent` без ключа и `unknown`, когда нет ни того, ни другого.
Чтение `/stats` открытого набора без его токена по-прежнему заменяет все метки
на `(аноним)`.
