Файл документирует четыре мета-инструмента, которые видит клиент, с точными
формами ответов и текстами ошибок.

# Мета-инструменты

Набор выставляет ровно четыре инструмента MCP. Нижестоящие инструменты клиенту
не показываются; до них доходят через `invoke_command`.

| инструмент | назначение |
| --- | --- |
| `list_servers` | инвентарь со здоровьем и тегами |
| `list_commands` | имена инструментов одного или нескольких серверов |
| `describe_commands` | входные схемы названных инструментов |
| `invoke_command` | вызвать один нижестоящий инструмент |

Каждая ошибка ниже возвращается обычным результатом инструмента с
`isError: true` и одним текстовым элементом, текст которого начинается с
`Error: `. Сам вызов MCP при этом не падает.

## list_servers

Вход: `{"filter": "code"}` (`filter` необязателен). Фильтр сравнивается без
учёта регистра с именем, описанием и тегами **до** любого подключения:
отфильтрованный сервер никогда не опрашивается.

```json
{
  "servers": [
    {
      "name": "echo",
      "type": "stdio",
      "enabled": true,
      "healthy": true,
      "tags": ["fixture"]
    }
  ],
  "version": "dev",
  "pid": 666441
}
```

| поле | значение |
| --- | --- |
| `name` | имя сервера |
| `description` | есть, когда в конфигурации задано |
| `type` | `stdio` или `remote` |
| `enabled` | из конфигурации; выключенный сервер не опрашивается и показывается как `healthy: true` |
| `healthy` | результат опроса; `false` при битой конфигурации или неудачном подключении |
| `error` | текст ошибки опроса, есть при `healthy: false` |
| `tags` | из конфигурации, когда заданы |
| `version` | версия сборки прокси |
| `pid` | pid процесса прокси |

Опросы здоровья идут параллельно, не больше 8 одновременно, с таймаутом 15 с и
кэшем на 15 с, который запоминает и неудачи.

## list_commands

Вход — одна из двух форм:

| вход | выход |
| --- | --- |
| `{"server": "alpha"}` | массив инструментов |
| `{"servers": ["alpha", "beta"]}` | объект с ключами по имени сервера, каждое значение — массив; у упавшего сервера — `{"error": "…"}` |
| оба | `Error: укажи server или servers, не оба` |
| ни одного | `Error: нужен параметр server или servers` |

С `servers` один `requestTimeout` ограничивает весь вызов, а не каждый сервер.

```json
[
  {
    "server": "echo",
    "name": "echo",
    "command": "echo",
    "description": "Echo the given text back."
  }
]
```

`name` — каноническое поле; `command` повторяет его для клиентов, написанных под
старую форму. `description` есть, когда сервер его предоставляет. Пагинация
проводится до конца, с потолком 20 страниц.

Один упавший сервер не скрывает остальные: его значение — `{"error": "…"}`,
а ошибку инструмент возвращает, только если не ответил ни один.

## describe_commands

Вход: `{"server": "echo", "command_names": ["echo", "nope"]}`; оба поля
обязательны.

```json
{
  "commands": [
    {
      "name": "echo",
      "description": "Echo the given text back.",
      "inputSchema": {
        "type": "object",
        "properties": {"text": {"type": "string"}},
        "required": ["text"]
      }
    }
  ],
  "missing": ["nope"]
}
```

`missing` присутствует всегда и перечисляет имена, которых сервер не
выставляет; они не валят вызов. `outputSchema` появляется, когда нижестоящий
инструмент его объявляет.

## invoke_command

Вход:

```json
{
  "server": "echo",
  "command_name": "echo",
  "parameters": {"text": "hello"}
}
```

| поле | значение |
| --- | --- |
| `server` | обязательно |
| `command_name` | обязательно |
| `parameters` | необязательный объект; `null` и пустая строка означают `{}` |

Аргументы нижестоящего инструмента кладутся **внутрь** `parameters`. Любой
другой ключ верхнего уровня — ошибка, поэтому вызов не может молча уйти с
пустыми аргументами:

```text
Error: лишние ключи: path — аргументы инструмента кладутся в parameters
```

Результат нижестоящего сервера возвращается как есть: `content`,
`structuredContent` и `isError` сохраняются. Если нижестоящий сервер закрывает
сессию (`ErrConnectionClosed`), прокси переподключается один раз и повторяет
вызов; вторая неудача возвращается с её причиной. `requestTimeout`, когда
задан, применяется к одному вызову.

## Разрешения

Блок allow/deny проверяется до подключения сервера; см.
[configuration.md](configuration.md#разрешения). Запрещённый вызов возвращает:

```json
{
  "isError": true,
  "content": [{"type": "text", "text": "🚫 Blocked by mcprig policy: no destructive SQL"}],
  "_meta": {"lazyMcpPolicy": "blocked"}
}
```

Маркер `_meta.lazyMcpPolicy` — то, что ищут хуки хоста.

## Счётчики

Каждый завершённый `invoke_command` считается в процессе набора: по клиенту, по
серверу и по инструменту, с p50/p95 и кольцом последних вызовов. Результат
нижестоящего сервера с `isError: true` считается провалом. Панель читает это
через `GET /stats`; stdio-режим счётчики не собирает.
