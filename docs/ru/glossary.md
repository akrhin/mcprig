# Словарь

Слова, которые эта документация употребляет узко, и откуда они взялись. Где
термин — ключ конфига, ключ и написан как в файле.

**набор (set)** — именованная группа MCP-серверов, выставленная на одной точке,
со своим портом и своим ключом. Набор описывается одним `servers.json` и живёт
отдельным процессом (`mcprig serve --config …`) под супервизией панели. Все пять
мета-инструментов принадлежат набору, а один и тот же сервер может стоять в двух
наборах двумя независимыми процессами. См.
[configuration.md](configuration.md#верхний-уровень) и
[architecture.md](architecture.md#один-процесс-на-набор).

**мета-тул (meta-tool)** — одна из пяти записей `tools/list`, которые видит
клиент набора: `list_servers`, `list_commands`, `describe_commands`,
`invoke_command`, `invoke_many`. Инструменты серверов за набором клиенту не
показываются никогда; до них доходят через `invoke_command`. См.
[meta-tools.md](meta-tools.md).

**downstream** — настоящий MCP-сервер за прокси: stdio-процесс, который mcprig
спавнит сам, или удалённая HTTP-точка. Go-пакет — `internal/downstream`. Тот же
сервер называют **upstream**, когда важно направление одного вызова (сервер
стоит выше по ходу запроса); здесь это одно и то же.

**tool-out** — `${MCPRIG_DATA_DIR:-$TMPDIR}/tool-out/`, куда целиком пишется
ответ, обрезанный `maxBytes`, и путь из маркера обрезки. Файлы живут 24 часа;
каталог ограничен 256 МиБ, первыми уходят старые. У каждого набора свой
`sets/<id>/tool-out/`. См. [cli.md#срок-жизни-tool-out](cli.md#срок-жизни-tool-out).

**песочница (sandbox)** — блок `sandbox` в записи сервера: `bwrap` (bubblewrap)
плюс `prlimit`, что даёт stdio-серверу своё дерево монтирования, корень только
для чтения, без `/home` и без сети хоста. По умолчанию `mode: bwrap`,
`mode: none` выключает; `onUnavailable` решает, что делать, когда bubblewrap
запуститься не может — `deny` (fail-closed, умолчание), `warn` или `allow`.
Сервер с тегом `untrusted` принимает только `deny`. См.
[configuration.md#песочница](configuration.md#песочница).

**хук (hook)** — клиентский плагин, который меняет то, что сказано агенту, а не
то, что делает прокси. В этом проекте слово означает хук маршрута: плагин
opencode (`mcprig-route.ts`), который кладёт в контекст агента строку «MCP живёт
за mcprig», чтобы тот перестал искать отдельные серверы. Замысел и выбранный
вариант — в архиве, [history/proposals/0001-route-hook.md](../history/proposals/0001-route-hook.md).

**warm (прогрев)** — заранее загрузить кэш инструментов набора, до того как
спросит клиент: `mcprig warm` зовёт `list_servers`, затем один `list_commands`
*без* `refresh` (этот флаг кэш, наоборот, чистит). Следующий вызов клиента
отвечает за миллисекунды вместо ожидания, пока распакуется каждый нижестоящий.
`deploy/mcprig-warm.timer` повторяет это каждые десять минут. См.
[cli.md#warm](cli.md#warm).

**ключ (key)** — bearer-токен, который требует закрытый набор; фрагмент клиента с
ним печатает `mcprig init`. Метка в счётчиках — заметка ключа, если владелец её
задал, иначе `key:<6 hex>/<User-Agent>`: короткий отпечаток ключа плюс
User-Agent. См. [meta-tools.md#счётчики](meta-tools.md#счётчики).

**открытый набор (open set)** — набор с `transport.allowAnonymous: true`:
заголовок `Authorization` не нужен. Он же *отвергает* любой присланный заголовок,
потому что сравнивать его не с чем.

**мягкий отказ (soft fail)** — как обрабатывается одна битая запись сервера:
сервер сохраняет `_configError`, показывается как `healthy: false`, а остальной
набор стартует. Это намеренно — см.
[configuration.md#мягкий-отказ](configuration.md#мягкий-отказ).

**каталог состояния (state directory)** — `MCPRIG_DATA_DIR`, по умолчанию
`~/.local/state/mcprig`, создаётся `0700`: `registry.json`, `env.json`,
`manager.pid` и на каждый набор
`sets/<id>/{servers.json,mcprig.log,oauth.json,stats,tool-out}`. См.
[install.md#состояние-на-диске](install.md#состояние-на-диске).
