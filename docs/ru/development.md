Файл охватывает сборку, тестовые ворота, контрактный набор и живой стенд на
настоящих MCP-серверах.

# Разработка

## Требования

- Go 1.27 (`go.mod` просит `1.27.3`; при `GOTOOLCHAIN=auto` тулчейн
  скачивается при первой сборке).
- `bash` и `curl` для скриптов.
- Необязательно для живого стенда: serena на `127.0.0.1:8899`, `npx` и `xerj`
  в `~/.local/bin`.

## Сборка и тесты

```bash
go build ./...
go vet ./...
go test ./... -race -count=1 -p 1
```

Набор с race — ворота этапа. Он покрывает загрузку конфигурации, оба транспорта,
пять мета-инструментов, разрешения, OAuth против фейкового сервера авторизации,
правила HTTP-транспорта, API менеджера, надзор и статистику.

`-p 1` обязателен: `internal/manager` и `e2e` поднимают настоящие наборы в общем
диапазоне 9100–9199 и при параллельном прогоне пакетов отбирают порт друг у друга.

Полезные узкие прогоны:

```bash
go test ./internal/config -run TestLoad -v
go test ./e2e -run TestLifecycle -v   # панель + набор + stdio-нижестоящий, без подготовки
```

`e2e/lifecycle_test.go` собирает настоящий бинарник и использует
`internal/manager/testdata/fakeset` как нижестоящий сервер, поэтому внешние
службы ему не нужны. Это самый быстрый способ увидеть всю цепочку в работе.

## Контрактный набор

`scripts/contract-e2e.sh` гоняет `go test ./e2e -run TestContract` против живого
менеджера:

```bash
E2E_BASE=http://127.0.0.1:9091 ./scripts/contract-e2e.sh
```

| переменная | по умолчанию | значение |
| --- | --- | --- |
| `E2E_BASE` | `http://127.0.0.1:9091` | панель под тестом |
| `E2E_STRICT` | `1` | `1` валит на известных дефектах эталона; `0` понижает их до строк лога |
| `E2E_AUTH` | не задана | `1` дополнительно проверяет, что API требует аутентификацию; нужна панель под паролем |

Тот же набор гоняется против эталона на TypeScript (`E2E_STRICT=0`) и против
этого бинарника (`E2E_STRICT=1`). Проверки выведены из
[контракта менеджера на TS](../reference/ts-manager-contract.md) (на русском).

Пустой `E2E_BASE` пропускает набор; при `E2E_STRICT=1` он выходит с ненулевым
кодом, чтобы пропущенный прогон не читался как пройденные ворота.

## Живой стенд

`scripts/dev-real-set.sh` собирает бинарник, поднимает панель с выключенной
аутентификацией, добавляет три настоящих сервера, создаёт открытый набор и
запускает его:

```bash
bash scripts/dev-real-set.sh
# панель:  http://127.0.0.1:9177   (аутентификация выключена, данные /tmp/mcprig-dev-real)
# набор:   http://127.0.0.1:9101/mcp  (открыт, без ключа)
# лог:     /tmp/mcprig-dev-real/sets/real/mcprig.log
bash scripts/dev-real-set.sh stop
```

| переменная | по умолчанию | значение |
| --- | --- | --- |
| `PANEL_PORT` | `9177` | порт панели |
| `SET_PORT` | `9101` | порт набора |
| `DATA` | `/tmp/mcprig-dev-real` | каталог состояния, pid-файл и бинарник |

Скрипт регистрирует:

| сервер | как подключается |
| --- | --- |
| `serena` | `http://127.0.0.1:8899/mcp` |
| `socraticode` | `npx -y socraticode@1.16.1` |
| `xerj` | `$HOME/.local/bin/xerj mcp` |

Ему нужно, чтобы эти трое были доступны; иначе набор всё равно стартует, а эти
серверы показываются нездоровыми. Печатаемый пример вызывает `activate_project`
через `invoke_command` и возвращает корень репозитория. `stop` убивает панель по
её pid-файлу; набор выходит вместе с панелью.

Логи: панель пишет `$DATA/panel.log`, набор пишет
`$DATA/sets/real/mcprig.log`.

## Релизная сборка

`.goreleaser.yaml` — определение релиза (`goreleaser release --snapshot
--clean` для локальной проверки). Архивы собирает и публикует CI по тегу `v*`
(Gitea, зеркало на GitHub); заметки релиза — раздел `CHANGELOG.md` для тега
через `scripts/release-notes.sh`. Сам `goreleaser` на хосте разработки не
установлен.
