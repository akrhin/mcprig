Файл перечисляет все подкоманды и флаги с настоящими примерами и их выводом.

# CLI

У `mcprig` десять подкоманд. Запуск без подкоманды равнозначен `mcprig serve`;
запуск только с флагами (`mcprig -config …`) — тоже `serve`.

| команда | назначение |
| --- | --- |
| `serve` | один набор как HTTP-точка MCP |
| `stdio` | один набор через stdin/stdout, запускается клиентом |
| `auth` | авторизовать сервер, которому нужен OAuth: печатает ссылку, сохраняет токен |
| `panel` | менеджер и веб-панель (реестр, наборы, ключи, хвост вызовов) |
| `init` | напечатать фрагмент конфигурации клиента; ничего не пишет |
| `doctor` | отчёт за один проход: конфиг, наборы, ключи, секреты, служебное, песочница |
| `warm` | загрузить кэш инструментов набора, чтобы первый вызов клиента был быстрым |
| `approve` | одобрить дескриптор инструмента, изменившийся под карантином |
| `status` | здоровье панели и состояние наборов в терминале |
| `logs` | хвост лога набора или сервера, с `-f` |

Коды возврата: `0` после показа справки, `2` для ошибки командной строки (неизвестная
подкоманда, лишний позиционный аргумент, неизвестный клиент), `1` для ошибки
времени выполнения (нет конфигурации, порт занят, отказ стартовать без
аутентификации) и для отчёта `doctor` или `warm` хотя бы с одной проблемой.

## serve

```bash
mcprig serve --config ~/.config/mcprig/sets/demo/servers.json
```

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-config` | `os.UserConfigDir()/mcprig/servers.json` (Linux: `~/.config/mcprig/servers.json`) | конфигурация набора |
| `-addr` | из `transport.host` и `transport.port`, иначе `127.0.0.1:9100` | адрес прослушивания; перекрывает конфигурацию |
| `-version` | | напечатать версию сборки и выйти |

`-addr` меняет только слушателя; `transport.path` (по умолчанию `/mcp`),
`authToken`, `allowAnonymous` и `allowedHosts` по-прежнему берутся из файла.
Пустой `authToken` — ошибка старта, если `allowAnonymous` не true.

Вывод идёт в stderr:

```text
time=2026-11-09T00:10:09.939+03:00 level=INFO msg="прокси слушает" addr=127.0.0.1:9184 servers=2
```

`servers` считает пригодные записи: включённые и без ошибки конфигурации.

Слушатель поднимается раньше, чем тронут хоть один нижестоящий сервер, и сразу
после этого все включённые серверы прогреваются в фоне: первый клиентский вызов
после прогрева отвечает за миллисекунды, а не ждёт распаковки одиннадцати
`npx`/`uvx`-серверов. `MCPRIG_PPROF=127.0.0.1:6060` открывает `net/http/pprof`
на этом адресе для любой подкоманды; по умолчанию выключен, наружу ничего не
выставлено.

### Срок жизни tool-out

Усечённый ответ лежит в `${MCPRIG_DATA_DIR:-$TMPDIR}/tool-out/`. `serve`,
`stdio` и `panel` чистят этот общий каталог при старте, а дальше каждые десять
минут — до выхода процесса; stdio берёт базовый каталог, а не свой:

| переменная | по умолчанию | значение |
| --- | --- | --- |
| `MCPRIG_TOOLOUT_TTL` | `24h` | файлы старше удаляются; синтаксис `time.ParseDuration` |
| `MCPRIG_TOOLOUT_MAX` | `256MiB` | предел объёма каталога tool-out; первыми уходят самые старые, единицы `B`/`K`/`KiB`/`M`/`MiB`/`G`/`GiB` |

Файл моложе пяти минут никогда не удаляется по объёму — клиент может ещё
читать путь из маркера усечения. Неразобранное значение пишет предупреждение в
лог, и берётся умолчание. `mcprig doctor` показывает число файлов, объём и
возраст самого старого.

## stdio

```bash
mcprig stdio --config ~/.config/mcprig/sets/demo/servers.json
```

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-config` | тот же дефолт, что у `serve` | конфигурация набора |

Ни слушателя, ни ключа нет: процессом владеет клиент, а граница — транспорт.
Прокси пишет сообщения MCP в stdout, логи — в stderr. `transport` в файле
игнорируется. Вызовы считаются и пишутся в историю, как у набора:
`$MCPRIG_DATA_DIR/stdio/stats/` держит те же `raw-YYYY-MM-DD.jsonl`,
`day-*.json` и `month-*.json`, поэтому разбивку по периодам можно прочитать обратно;
клиент всегда `stdio` — транспорт и есть единственный клиент процесса. Если
каталог не открылся, в stderr уходит предупреждение, а прокси продолжает
обслуживать. Нижестоящие stdio-серверы открываются рукопожатием `initialize` (ревизия `2025-11-25`),
которое понимают все; HTTP-нижестоящие остаются на современном
`server/discover`.

## auth

```bash
mcprig auth --set main swaggerhub
```

Печатает ссылку авторизации и ждёт редирект; браузер не запускает, поэтому
команда годится и по SSH, и на машине без графической сессии. Токен пишется в
`oauth.json` набора — `<каталог данных>/sets/<id>/oauth.json`, — откуда процесс
набора читает его при следующем старте; после этого набор надо перезапустить в
панели.

| флаг | по умолчанию | смысл |
| --- | --- | --- |
| `-set` | | имя набора: конфиг и хранилище токенов берутся из его каталога |
| `-config` | | `servers.json` вместо `-set`; токен тогда ложится в каталог данных процесса |
| `-timeout` | `6m` | сколько ждём, пока ссылка не будет использована |

Позиционный аргумент — имя сервера. Сервер, которому OAuth не нужен, просто
подключается, и команда сообщает об этом.

То же самое панель делает из браузера: кнопка **авторизовать** в строке сервера,
ссылка в диалоге, код возвращается на адрес панели — см.
[panel.md](panel.md#oauth). У CLI остаётся loopback-приёмник, и это то, что
принимает провайдер, требующий `https` для любого другого адреса.

Интерактивный поток намеренно не запускается внутри запроса клиента:
health-проба набора ждёт 15 с, а человеку у браузера нужны минуты. Пока токена
нет, набор показывает сервер нездоровым — `auth` и есть выход.

## panel

```bash
MCPRIG_PASSWORD='change-me' mcprig panel
```

Флагов нет. Всё задаётся окружением:

| переменная | по умолчанию | значение |
| --- | --- | --- |
| `MCPRIG_DATA_DIR` | `$XDG_STATE_HOME/mcprig`, иначе `~/.local/state/mcprig` | реестр, ключи, логи, токены OAuth |
| `MCPRIG_HOST` | `127.0.0.1` | адрес прослушивания панели |
| `MCPRIG_PORT` | `9091` | порт панели |
| `MCPRIG_PUBLIC_URL` | пусто | публичный адрес панели, `http(s)://host[:port][/prefix]`; когда задан — единственный источник redirect OAuth и решения о `Secure`-cookie. Проверяется на старте: схема, хост, без query/fragment, без хвостового `/` |
| `MCPRIG_TLS_CERT` | пусто | сертификат слушателя панели; задаётся вместе с `MCPRIG_TLS_KEY` — одно поле без другого отбивает старт, нечитаемый файл тоже |
| `MCPRIG_TLS_KEY` | пусто | ключ слушателя панели |
| `MCPRIG_CLI` | запущенный исполняемый файл | бинарник, запускаемый для каждого набора (`serve --config …`) |
| `MCPRIG_BIND_IP` | `0.0.0.0` | `transport.host`, записываемый в `servers.json` каждого набора |
| `MCPRIG_SEED_FILE` | пусто | JSON с `servers[]` и `sets[]`; используется, только когда реестр пуст; для закрытых наборов генерируются новые ключи |
| `MCPRIG_PASSWORD` | пусто | пароль панели |
| `MCPRIG_PASSWORD_HASH` | пусто | `scrypt$N$r$p$salt$hash`; если задан, простой пароль игнорируется |
| `MCPRIG_PROXY_SECRET` | пусто | общий секрет для прокси-аутентификации; значение короче 32 символов пишет предупреждение в лог |
| `MCPRIG_TRUSTED_PROXIES` | loopback | IP или CIDR через запятую, чьим `X-Forwarded-*` верят; запись, которая не разбирается, останавливает панель на старте |
| `MCPRIG_USER` | `admin` | имя для входа |
| `MCPRIG_USER_HEADER` | `Remote-User` | заголовок с именем пользователя от доверенного прокси |
| `MCPRIG_ALLOWED_HOSTS` | только loopback | список разрешённых `Host` через запятую |
| `MCPRIG_AUTH` | пусто | `off` отключает аутентификацию панели |

Доверие `X-Forwarded-*` включается *заданием* `MCPRIG_PROXY_SECRET` и только
от пира, которому панель верит: loopback или адрес из
`MCPRIG_TRUSTED_PROXIES`. Запрос с любого другого пира считается пришедшим без
этих заголовков — ни публичного имени, ни `https`, ни адреса клиента для лимита
входа. Прокси на другой машине требует и секрета, и его адреса в списке; при
расхождении панель отвечает `403` на проверке origin, хотя прокси работает
исправно. У `http`-панели с секретом браузерные записи отбиваются — запрос
считается `https`; задайте `MCPRIG_PUBLIC_URL=https://…` под то, что видит
браузер.

Режимы аутентификации выводятся из заданной конфигурации:

| пароль | прокси-секрет | `MCPRIG_AUTH` | режим |
| --- | --- | --- | --- |
| любой | любой | `off` | нет |
| да | нет | | пароль |
| нет | да | | прокси |
| да | да | | прокси + пароль |

Без всего этого панель отказывается стартовать:
`API открыт: задайте MCPRIG_PASSWORD или MCPRIG_AUTH=off`.

`MCPRIG_BIND_IP=0.0.0.0` — дефолт для слушателей **наборов**, а не для панели.
Наборы защищены своими bearer-ключами; сама панель по-прежнему привязывается к
loopback, если `MCPRIG_HOST` не говорит иного.

```text
2026/11/09 00:05:27 WARN менеджер: MCPRIG_ALLOWED_HOSTS пуст — принимаются только loopback-хосты
2026/11/09 00:05:27 WARN панель без пароля (MCPRIG_AUTH=off): доступна всем, кто дотянется до порта; задайте MCPRIG_PASSWORD
2026/11/09 00:05:27 INFO менеджер запущен addr=127.0.0.1:9080 scheme=http publicUrl= data=/var/lib/mcprig auth=none
```

`MCPRIG_PUBLIC_URL` — адрес, по которому панель доступна снаружи. Это
единственный источник redirect OAuth (`<publicUrl>/oauth/callback`, префикс пути
сохраняется), и он же решает, что cookie сессии получает `Secure`; без него
redirect по-прежнему собирается из `MCPRIG_HOST` и `MCPRIG_PORT`. Значение,
которое не разбирается, без хоста, с query или fragment, с хвостовым `/`
останавливает панель на старте.

С `MCPRIG_TLS_CERT` и `MCPRIG_TLS_KEY` панель сама слушает https; cookie сессии
получает `Secure` всегда, когда публичный адрес `https` или у панели свой
сертификат, — хотя TLS-прокси отдаёт процессу открытый http. `X-Forwarded-Proto`
и `X-Forwarded-Host` доверяются только при заданном `MCPRIG_PROXY_SECRET` **и**
пире из loopback или `MCPRIG_TRUSTED_PROXIES`: иначе они игнорируются — не
делают запрос `https` и не называют панель для проверок Host и Origin, а
redirect OAuth от них не зависит никогда.

Вторая панель на том же каталоге данных отказывается стартовать из-за
`manager.pid`.

## doctor

```bash
MCPRIG_DATA_DIR=~/.local/state/mcprig MCPRIG_PORT=9091 mcprig doctor
```

Один проход по тому, ради чего иначе приходится разбирать логи панели.
Запущенная панель не нужна: файловые проверки работают сами, а мёртвый
слушатель — это `проблема`, а не падение. Пароль панели читается сначала из
`~/.config/mcprig/panel.env`, затем из старого файла `env`; кавычки, `export` и
комментарии понимаются.

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-config` | `os.UserConfigDir()/mcprig/servers.json` | конфигурация клиента; если файла нет, серверы считаются из реестра |
| `-json` | | машинный отчёт с теми же разделами |

Разделов пять:

1. конфигурация — путь, число серверов, включённые;
2. наборы — id, порт, autostart, слушатель, код `/healthz`;
3. ключи — число и 8-символьный `keyPrefix` активного;
4. секреты `${VAR}` — только имена и источник (OpenBao, `env.json` или
   окружение), никогда значения;
5. служебные — чужие слушатели в `9100–9199`, размер `sets/*/oauth.json`,
   размер `tool-out/`, `/healthz` панели, эффективный redirect OAuth.

Строка с версией и путём к бинарю печатается над первым заголовком.
Песочница — строка внутри «служебных»: она запускает `bwrap` с user-namespace и
пишет `песочница: bwrap запускается, userns разрешён`, а если изоляцию кто-то
просит, а bwrap или userns недоступны — это проблема и код 1.

Код возврата: `0`, когда каждая строка `ok`, иначе `1`; последняя строка —
`итог: N проблем`. Порты наборов проверяются через `MCPRIG_BIND_IP` (wildcard
сводится к loopback); адрес панели берётся из `MCPRIG_HOST` и `MCPRIG_PORT`.

Там же печатается эффективный redirect OAuth, собранный из `MCPRIG_PUBLIC_URL`
(или адреса панели): нет хоста, порт `0` или loopback за `https` — проблема,
потому что провайдер не сможет прислать туда код.

Установка, которую ещё не делали, — не поломка: когда нет ни конфига клиента,
ни реестра, `doctor` печатает одну строку — `установка пуста: конфиг … и реестр
… не созданы, запустите mcprig init` — затем `итог: 0 проблем` и код `0`.
Реестр, который есть, но не разбирается, остаётся проблемой (код `1`). В `-json`
пустые разделы — `[]`, а не `null`, чтобы потребителю не приходилось отличать
«данных ещё нет» от «не читали».

При `MCPRIG_AUTH=off` без `MCPRIG_PASSWORD` и `MCPRIG_PASSWORD_HASH` в
«служебных» появляется предупреждение — `предупреждение: панель без пароля …`:
открытая панель доступна всем, кто дотянется до порта. Это предупреждение, а не
проблема, поэтому код возврата остаётся `0`.

```text
mcprig doctor, версия dev (/usr/local/bin/mcprig)

[конфиг]
ok: конфиг /home/user/.config/mcprig/servers.json: 11 серверов, 11 включено

[наборы]
ok: example: порт 9101, слушает, autostart, /healthz 200

[ключи]
ok: example: 3 ключа, активный eef8bf86

[секреты]
ok: CONTEXT7_API_KEY: окружение

[служебные]
ok: чужие порты в диапазоне 9100–9199: 9119 (выдача портов их пропускает)
ok: sets/*/oauth.json нет
ok: tool-out нет
ok: панель 127.0.0.1:9091: /healthz 200
ok: redirect OAuth: http://127.0.0.1:9091/oauth/callback

итог: 0 проблем
```

## warm

```bash
mcprig warm --set example
mcprig warm --all --panel http://127.0.0.1:9091 --password "$MCPRIG_PASSWORD"
mcprig warm --config ~/.config/mcprig/sets/demo/servers.json
```

`warm` загружает кэш инструментов набора: `list_servers`, затем один
`list_commands` без `refresh` (с этим флагом кэш, наоборот, сбрасывается).
Следующий вызов клиента отвечает за миллисекунды, а не ждёт распаковки всех
даунстримов. Путь тот же, что у клиента: HTTP-запрос MCP к набору либо, с
`-config`, `internal/mcpserver` в своём процессе без сети.

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-url` | пусто: адрес набора берётся из `/api/sets` панели | прямой MCP-адрес набора (`http://127.0.0.1:9101/mcp`), панель не нужна |
| `-panel` | `MCPRIG_PANEL_URL`, иначе `http://127.0.0.1:$MCPRIG_PORT` | адрес панели: порт набора для `-set` и все наборы для `-all` |
| `-set` | `main` | имя набора: файл токена и строка отчёта |
| `-all` | | все наборы из панели; по строке на набор |
| `-timeout` | `2m` | бюджет на один набор |
| `-token` | пусто | bearer-ключ (виден в `ps`; лучше `-token-file`) |
| `-token-file` | пусто | файл с bearer-ключом |
| `-config` | пусто | локальный `servers.json`: прогрев в процессе, без сети |
| `-json` | | те же строки массивом `{set, tools, ms, error}` |
| `-password` | `MCPRIG_PASSWORD` | пароль панели для `-all` и для резолва порта по имени набора |
| `-secret` | `MCPRIG_PROXY_SECRET` | секрет обратного прокси панели для `-all` |
| `-user` | `admin` | имя пользователя панели |

Порядок токена: `-token`, `-token-file`, `MCPRIG_TOKEN`, затем
`~/.config/mcprig/<set>.token`; если нет ни одного, команда падает с подсказкой
`mcprig init`. Открытый набор прогревается без ключа.

```text
example: 421 инструмент(ов), 5.6 мс
итог: 1 набор, 421 инструмент(ов), 5.6 мс
```

`-json` печатает те же строки:

```json
[
  {
    "set": "example",
    "tools": 421,
    "ms": 5.6
  }
]
```

Код возврата: `0`, когда прогреты все наборы, `1`, если хотя бы один не
прогрелся (панель недоступна, нет ключа, таймаут); строка с ошибкой несёт
причину. `deploy/mcprig-warm.timer` повторяет это каждые десять минут — см.
`deploy/README.md`.

## approve

```bash
mcprig approve --set main serena/find_symbol
mcprig approve --set main serena/find_symbol gitea/create_pull_request
mcprig approve --set main --all
```

Инструмент, дескриптор которого изменился после одобрения, стоит в карантине:
прокси отбивает его вызовы, пока человек не одобрит новый дескриптор
([meta-tools.md](meta-tools.md#карантин-дескрипторов)). Отказ называет эту
команду. Первое появление инструмента одобряется само, поэтому `approve`
занимается только настоящей сменой.

Запись принадлежит панели: команда читает и пишет её через API панели — те же
два маршрута, что у дровера **Инструменты**. `--all` берёт все изменившиеся
инструменты набора; без него каждый аргумент — один `server/tool`.

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-set` | `main` | имя набора |
| `-all` | | одобрить все изменившиеся инструменты набора |
| `-panel` | `MCPRIG_PANEL_URL`, иначе `http://127.0.0.1:$MCPRIG_PORT` | адрес панели |
| `-password` | `MCPRIG_PASSWORD` | пароль панели |
| `-secret` | `MCPRIG_PROXY_SECRET` | секрет обратного прокси панели |
| `-user` | `admin` | пользователь панели для входа |

```text
набор main: одобрен serena/find_symbol
```

`--all` перечисляет одобренное:

```text
набор main: одобрено 2
  gitea/create_pull_request
  serena/replace_symbol_body
```

Инструмент, который не менялся, панель отвергает — `нечего одобрять:
serena/find_symbol не менялся или неизвестен` — и команда завершается с `1`.

Запись пишет панель, `approvedBy: "panel"`: дровер и эта команда — один клиент
одного API, своего имени у CLI нет. Код возврата: `0` — одобрено всё, что
просили (`--all` без изменённых тоже `0`); `1` — панель отвергла инструмент
(не менялся или неизвестен) или запрос не прошёл; `2` — ошибка в аргументах
(и `--all`, и список, или ни того ни другого).

## status

```bash
mcprig status
mcprig status --panel http://127.0.0.1:9091 --json
mcprig status --set example
```

Один снимок того, что показывает панель: `/healthz` (публичный, поэтому
мёртвая панель — ошибка с адресом, а не трейсбек) и `/api/state` (каждый набор
с портом, состоянием, ключом и ошибкой запуска). Число инструментов и время
последнего вызова берутся из `/api/calls`: `0` и `—` значат, что набор
остановлен или этот запрос не ответил — он необязательный и команду не валит.

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-panel` | `MCPRIG_PANEL_URL`, иначе `http://127.0.0.1:$MCPRIG_PORT` | адрес панели |
| `-set` | пусто: все наборы | один набор по id |
| `-json` | | `{panel, health, sets: [{id, name, state, port, tools, key, lastCall, error}]}` |
| `-timeout` | `10s` | бюджет на весь отчёт |
| `-password` | `MCPRIG_PASSWORD` | пароль панели (в вывод не попадает) |
| `-secret` | `MCPRIG_PROXY_SECRET` | секрет обратного прокси панели |
| `-user` | `admin` | имя пользователя панели |

```text
mcprig status, панель http://127.0.0.1:9091
здоровье: ok

набор    состояние   порт  инструментов  ключ  последний вызов
example  запущен     9101  12            есть  2026-11-15 13:00:11
lab      остановлен  9102  —             нет   —

итог: 2 набора
```

Код возврата: `0`, когда панель ответила; `1` иначе (недоступна, `401` —
добавьте `-password` или `-secret`, неизвестный `-set`).

## logs

```bash
mcprig logs --set example
mcprig logs --set example --server context7 -n 50
mcprig logs --set example -f --json
```

`logs` читает `/api/sets/<id>/logs`, а с `-server` —
`/api/sets/<id>/servers/<name>/logs`, передавая тот же параметр `lines`, что и
панель. С `-f` опрос раз в секунду, печатаются только ещё не показанные строки;
Ctrl-C завершает с кодом `0`. Исключение — повторяющийся лог: когда весь ответ
целиком оказывается хвостом предыдущего и при этом не совпадает с ним, `logs`
печатает ответ снова, а не молчит — у хвоста панели нет курсора.
`-json` печатает по объекту на строку:
`{"set","server","line","ts"}`, когда панель отдаёт структуру, и `{"line":"…"}`,
пока она отдаёт простые строки.

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-panel` | `MCPRIG_PANEL_URL`, иначе `http://127.0.0.1:$MCPRIG_PORT` | адрес панели |
| `-set` | обязательно | набор, чей лог читается |
| `-server` | пусто: весь набор | лог одного сервера |
| `-n` | `200` | сколько последних строк взять |
| `-f` | | следить: опрос раз в секунду, только новые строки |
| `-json` | | по объекту на строку |
| `-password` | `MCPRIG_PASSWORD` | пароль панели (в вывод не попадает) |
| `-secret` | `MCPRIG_PROXY_SECRET` | секрет обратного прокси панели |
| `-user` | `admin` | имя пользователя панели |

Код возврата: `0` по концу лога и по Ctrl-C, `1`, когда панель отказала
(неизвестный набор или сервер, `401`, недоступна).

## init

`init` печатает фрагмент для собственного файла конфигурации клиента. Сам он
этот файл никогда не правит.

```bash
mcprig init --client opencode --set demo --config ~/.config/mcprig/sets/demo/servers.json
```

| флаг | по умолчанию | значение |
| --- | --- | --- |
| `-client` | `opencode` | одно из `opencode`, `claude`, `codex` |
| `-set` | `demo` | имя набора в сгенерированном имени сервера (`mcprig-<set>`) |
| `-remote` | пусто | URL набора, например `http://127.0.0.1:9100/mcp`; пусто означает stdio |
| `-key` | пусто | bearer-токен для `--remote`; `-` читает stdin |
| `-key-file` | пусто | файл с bearer-токеном; предпочтительнее `-key`, чьё значение видно в `ps` и истории шелла |
| `-binary` | `mcprig` | путь к бинарнику для stdio-режима |
| `-config` | пусто | путь к `servers.json` для stdio-режима (обязателен) |

Приоритет ключа: `-key-file`, затем `-key` (`-` значит stdin), затем
`MCPRIG_KEY`.

### Вывод stdio

```bash
mcprig init --client opencode --set demo --config /tmp/demo/servers.json
```

```json
{
  "mcp": {
    "servers": {
      "mcprig-demo": {
        "command": [
          "mcprig",
          "stdio",
          "--config",
          "/tmp/demo/servers.json"
        ],
        "enabled": true,
        "type": "local"
      }
    }
  }
}
```

```bash
mcprig init --client claude --set demo --config /tmp/demo/servers.json
```

```json
{
  "mcpServers": {
    "mcprig-demo": {
      "args": [
        "stdio",
        "--config",
        "/tmp/demo/servers.json"
      ],
      "command": "mcprig"
    }
  }
}
```

```bash
mcprig init --client codex --set demo --config /tmp/demo/servers.json
```

```toml
[mcp_servers.mcprig-demo]
command = "mcprig"
args = ["stdio", "--config", "/tmp/demo/servers.json"]
```

### Вывод remote

```bash
mcprig init --client opencode --set demo --remote http://127.0.0.1:9100/mcp --key-file ./demo.key
```

```json
{
  "mcp": {
    "servers": {
      "mcprig-demo": {
        "enabled": true,
        "headers": {
          "Authorization": "Bearer <token>"
        },
        "type": "remote",
        "url": "http://127.0.0.1:9100/mcp"
      }
    }
  }
}
```

Для `claude` корневой объект — `mcpServers`, а `type` — `http`; для `codex`
фрагмент — таблица `[mcp_servers.<name>]` с `url` и
`http_headers = { Authorization = "…" }`.

### Ошибки

| вход | код возврата | сообщение |
| --- | --- | --- |
| `--key` без `--remote` | 2 | `--key и --key-file нужны только с --remote: в stdio-режиме ключ не требуется` |
| `--remote` без ключа | 2 | `для --remote нужен ключ: --key, --key-file, --key - или MCPRIG_KEY` |
| stdio без `--config` | 2 | `для stdio-режима нужен --config (путь к servers.json набора)` |
| неизвестный клиент | 2 | `неизвестный клиент "nope"; доступны: opencode, claude, codex` |
| файл ключа отсутствует | 1 | `ключ: open /nope: no such file or directory` |

Справка CLI, диагностика и строки логов в этой сборке — на русском; в этом
документе они приведены как есть.
