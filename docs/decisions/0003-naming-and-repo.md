# 0003. Имя, репозиторий, метрика дашборда

- **Дата:** 2026-11-08
- **Статус:** принято (human-set, ответы владельца на форме)
- **Status:** superseded by PR #9 (module `github.com/akrhin/mcprig`)

## Контекст

Проект вырос из `lazy-mcp` (TS) как отдельный Go-репозиторий. Нужны были имя
продукта, место его жизни и единица измерения для дашборда; плюс решалась
судьба codemap-артефактов, оставшихся в замороженном `lazy-mcp`.

## Решение

1. **Имя — `mcprig`.** Свободно на npm, PyPI, crates.io и как логин GitHub;
   занятые кандидаты (`patchbay`, `stoa`, `portico`, `gatehouse`, …) и
   свободные альтернативы (`mcppier`, `mcpdeck`, `portrack`, …) — в отчёте
   по выбору имени.
2. **Репозиторий — Gitea, `<host>/mcprig`** (private), remote `origin`,
   ветка `master`. Модуль Go переименовывается в путь проекта после того, как
   закончат работу параллельные полосы правок.
3. **Метрика дашборда — собственный счётчик в `invoke_command`**: прокси сам
   считает вызовы, ошибки, латентность (p50/p95) и токены. Парсинг журнала
   наборов не используется: он не даёт токенов, хрупок к формату строк и
   отсутствует в stdio-режиме.
4. **Codemap-артефакты из `lazy-mcp` удалены** (8 файлов `codemap.md`,
   `.slim/codemap.json`, секция `## Repository Map` в `AGENTS.md`).
   Карта нужна этому проекту, а не замороженному эталону; снимать её здесь
   стоит, когда код перестанет двигаться под правками.

## Последствия

- README и `deploy/` живут в новом репозитории; `lazy-mcp` остаётся
  read-only эталоном контракта.
- Счётчик — часть `internal/mcpserver`; единица «вызов инструмента», ошибки и
  латентность считаются на прокси, а не на клиенте.
- **Метрика отдельная от stdout набора.** Счётчик живёт в процессе прокси и
  отдаётся снимком `GET /stats` (тот же bearer, что `/mcp`); панель его
  опрашивает. Журнал набора (`sets/<id>/lazy-mcp.log`) остаётся диагностикой:
  в нём нет ни токенов на вызов, ни атрибуции по харнесу.
- **Харнес называет себя сам:** `initialize` → `clientInfo.name/version`, для
  HTTP — ещё `User-Agent` и отпечаток ключа (`key:<6 hex>`), сам ключ не
  сохраняется. Списка клиентов в коде нет — новый харнес учитывается без правок.
