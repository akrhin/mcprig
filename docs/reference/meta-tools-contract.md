# Контракт мета-тулов

Пять инструментов, которые прокси отдаёт клиенту. Формы ответов — то, от чего
зависят агенты и промпты; менять их можно только здесь и с записью в
`docs/decisions/`.

## `list_servers`

Аргументы: `filter` (строка, необязательно) — ищет по имени, описанию и тегам.
Фильтр применяется **до** подключения: отфильтрованный сервер не поднимается.

```json
{
  "servers": [
    {
      "name": "alpha",
      "description": "основная БД",
      "type": "stdio",
      "enabled": true,
      "healthy": true,
      "tags": ["database", "postgres"]
    },
    {
      "name": "beta",
      "type": "remote",
      "enabled": false,
      "healthy": true
    }
  ],
  "version": "0.1.0",
  "pid": 313357
}
```

- `type` — `stdio` или `remote`.
- Выключенный сервер отдаётся `enabled:false, healthy:true` и не опрашивается:
  «выключен» — не «болен».
- Битый конфиг сервера — `healthy:false` и `error` с причиной; остальные
  серверы это не ломает.
- Опрос здоровья кэшируется на 15 с (включая ошибки), каждый сервер получает
  5 с, одновременно опрашивается не больше 8.
- `pid` — чтобы перечитать конфиг по `SIGHUP`; `version` — версия сборки.

## `list_commands`

Две формы аргументов, ровно как в lazy-mcp:

| аргументы | ответ |
| --- | --- |
| `{"server": "alpha"}` | массив команд |
| `{"servers": ["alpha", "beta"]}` | карта `{имя: [команды]}`; у упавшего сервера значение — `{"error": "…"}` |
| `{"prefix": "se"}` | с любой формой выше — только имена, начинающиеся с префикса (без учёта регистра) |
| оба сразу | ошибка |
| ни одного | ошибка `нужен параметр server или servers` |

`prefix` применяется на отдаче, после чтения списка: кэш схем не ломается,
следующий вызов без префикса видит все команды.

Один `requestTimeout` покрывает весь вызов с `servers`, а не каждый сервер.
Серверы обходятся параллельно, по восемь сразу. Список инструментов кэшируется
на время соединения; `{"refresh": true}` (у `list_commands` и
`describe_commands`) выбрасывает кэш и спрашивает серверы заново. Кэш также
сбрасывается, когда сервер присылает `notifications/tools/list_changed`, —
новый инструмент виден со следующего вызова без `refresh`.

```json
[
  { "server": "alpha", "name": "echo", "command": "echo" }
]
```

`name` — каноническое поле; `command` дублирует его для клиентов, написанных
под старую форму. `description` присутствует, если сервер её отдаёт.
Пагинация `tools/list` дочитывается по `NextCursor` (потолок 20 страниц).
Ошибку инструмент возвращает, только если не ответил ни один сервер списка.

## `describe_commands`

```json
{
  "commands": [
    {
      "name": "echo",
      "description": "Возвращает текст",
      "inputSchema": { "type": "object", "properties": { "text": { "type": "string" } } }
    }
  ],
  "missing": ["nope"]
}
```

Ненайденные имена не роняют вызов — попадают в `missing`.

## `invoke_command`

```json
{ "server": "alpha", "command_name": "echo", "parameters": { "text": "привет" } }
```

- Результат нижестоящего сервера отдаётся как есть (`content`, `structuredContent`,
  `isError`), пока он не длиннее `maxBytes` (по умолчанию 32768, допустимо до
  1048576, `0` — умолчание).
- Ответ длиннее `maxBytes` режется по границе UTF-8, текст заканчивается маркером
  `[обрезано: N из M байт, полный ответ — <путь>]`; полный ответ пишется с
  правами `0600` в `${MCPRIG_DATA_DIR:-$TMPDIR}/tool-out/<случайное>.txt`
  (каталог создаётся при первом использовании). Малое ответы не трогаются — ни
  файла, ни маркера. Нечисловой, отрицательный или превышающий 1048576
  `maxBytes` — ошибка аргумента.
- `command_name` обязателен, но `command` — его синоним (именно это имя отдаёт
  `list_commands`); два ключа с разными значениями — ошибка.
- `parameters` необязательны; `null` трактуется как `{}`.
- Любые ключи верхнего уровня, кроме перечисленных выше, — ошибка:
  `лишние ключи: path — допустимые: server, command_name, command, parameters, maxBytes; аргументы инструмента кладутся в parameters`.
  Это защита от тихого запуска инструмента с пустыми аргументами.
- Вызов повторяется один раз через 250 мс, только если соединение упало до
  первого байта ответа (`ErrConnectionClosed`, `io.EOF`, сетевая ошибка).
  Если ответ уже начал приходить или инструмент вернул `isError`, повтора нет —
  результат отдаётся как есть. `list_commands` и `describe_commands` не
  повторяются: у них свои таймауты.

**Срок жизни выгрузок.** Файлы `tool-out` не копятся вечно: `serve` и `panel`
удаляют их при старте и дальше раз в час, пока живёт процесс. Файл старше
`MCPRIG_TOOLOUT_TTL` (по умолчанию `24h`) удаляется; если каталог больше
`MCPRIG_TOOLOUT_MAX` (по умолчанию `256MiB`), первыми уходят самые старые.
Файл моложе пяти минут не удаляется по объёму: клиент может ещё читать путь из
маркера. Неразобранное значение переменной — предупреждение в лог и умолчание.

## `invoke_many`

```json
{
  "calls": [
    { "server": "alpha", "command_name": "echo", "parameters": { "text": "раз" } },
    { "server": "beta", "command_name": "search", "parameters": { "query": "два" } }
  ],
  "maxBytes": 4096
}
```

- `calls` обязателен: от 1 до 8 вызовов, каждый в форме `invoke_command`
  (`server`, `command_name` или его синоним `command`, необязательные `parameters`). Больше 8 — ошибка
  всего запроса.
- Вызовы идут параллельно: всего до 8 одновременно, к одному нижестоящему
  серверу — не больше 4. Один `requestTimeout` покрывает весь веер.
- Ответ — массив по элементу на вызов, **в порядке `calls`**:

  ```json
  [
    { "ok": true, "server": "alpha", "command_name": "echo", "result": "…", "ms": 12 },
    { "ok": false, "server": "beta", "command_name": "search", "error": "таймаут вызова 120000 мс", "ms": 120013 }
  ]
  ```

- `result` — то же, что вернул бы `invoke_command`: текст одиночного текстового
  элемента, иначе весь объект результата; к каждому ответу применяется тот же
  `maxBytes` (по умолчанию 32768).
- Упавший вызов (неизвестный или выключенный сервер, запрет правами, ошибка
  транспорта, таймаут, `isError: true` от нижестоящего сервера) не валит
  остальные: он остаётся на своём месте с `ok: false` и `error`.
- Невалидный вход — ноль вызовов, больше 8, лишний ключ внутри вызова, нет
  `server` либо обоих имён (`command_name`/`command`), `parameters` не объект,
  плохой `maxBytes` — валит весь
  запрос с `isError: true`, ничего не выполняется.

## Права

Политика проверяется **до** подключения. Порядок: правила сервера → глобальные
правила → `default` сервера → глобальный `default` → разрешено. Запрет
возвращается как результат с `isError` и `_meta.lazyMcpPolicy: "blocked"` —
этот признак ищут хост-хуки клиентов.
