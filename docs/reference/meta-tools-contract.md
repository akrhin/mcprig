# Контракт мета-тулов

Четыре инструмента, которые прокси отдаёт клиенту. Формы ответов — то, от чего
зависят агенты и промпты; менять их можно только здесь и с записью в
`docs/decisions/`.

## `list_servers`

Аргументы: `filter` (строка, необязательно) — ищет по имени, описанию и тегам.
Фильтр применяется **до** подключения: отфильтрованный сервер не поднимается.

```json
{
  "servers": [
    {
      "name": "alpha",
      "description": "основная БД",
      "type": "stdio",
      "enabled": true,
      "healthy": true,
      "tags": ["database", "postgres"]
    },
    {
      "name": "beta",
      "type": "remote",
      "enabled": false,
      "healthy": true
    }
  ],
  "version": "0.1.0",
  "pid": 313357
}
```

- `type` — `stdio` или `remote`.
- Выключенный сервер отдаётся `enabled:false, healthy:true` и не опрашивается:
  «выключен» — не «болен».
- Битый конфиг сервера — `healthy:false` и `error` с причиной; остальные
  серверы это не ломает.
- Опрос здоровья кэшируется на 15 с (включая ошибки), каждый сервер получает
  5 с, одновременно опрашивается не больше 8.
- `pid` — чтобы перечитать конфиг по `SIGHUP`; `version` — версия сборки.

## `list_commands`

Две формы аргументов, ровно как в lazy-mcp:

| аргументы | ответ |
| --- | --- |
| `{"server": "alpha"}` | массив команд |
| `{"servers": ["alpha", "beta"]}` | карта `{имя: [команды]}`; у упавшего сервера значение — `{"error": "…"}` |
| оба сразу | ошибка |
| ни одного | ошибка `нужен параметр server или servers` |

Один `requestTimeout` покрывает весь вызов с `servers`, а не каждый сервер.
Серверы обходятся параллельно, по восемь сразу. Список инструментов кэшируется
на время соединения; `{"refresh": true}` (у `list_commands` и
`describe_commands`) выбрасывает кэш и спрашивает серверы заново.

```json
[
  { "server": "alpha", "name": "echo", "command": "echo" }
]
```

`name` — каноническое поле; `command` дублирует его для клиентов, написанных
под старую форму. `description` присутствует, если сервер её отдаёт.
Пагинация `tools/list` дочитывается по `NextCursor` (потолок 20 страниц).
Ошибку инструмент возвращает, только если не ответил ни один сервер списка.

## `describe_commands`

```json
{
  "commands": [
    {
      "name": "echo",
      "description": "Возвращает текст",
      "inputSchema": { "type": "object", "properties": { "text": { "type": "string" } } }
    }
  ],
  "missing": ["nope"]
}
```

Ненайденные имена не роняют вызов — попадают в `missing`.

## `invoke_command`

```json
{ "server": "alpha", "command_name": "echo", "parameters": { "text": "привет" } }
```

- Результат нижестоящего сервера отдаётся как есть (`content`, `structuredContent`,
  `isError`).
- `parameters` необязательны; `null` трактуется как `{}`.
- Любые ключи верхнего уровня, кроме трёх перечисленных, — ошибка:
  `лишние ключи: path, query — аргументы инструмента кладутся в parameters`.
  Это защита от тихого запуска инструмента с пустыми аргументами.
- Если сервер закрыл сессию (`ErrConnectionClosed`), прокси один раз
  переподключается и повторяет вызов; вторая неудача возвращается с причиной.

## Права

Политика проверяется **до** подключения. Порядок: правила сервера → глобальные
правила → `default` сервера → глобальный `default` → разрешено. Запрет
возвращается как результат с `isError` и `_meta.lazyMcpPolicy: "blocked"` —
этот признак ищут хост-хуки клиентов.
