## Принято

**Этап 0 — контракт.** `e2e/contract_test.go` против живого TS-эталона
(`127.0.0.1:9091`) и против нашего `panel`: 11 контрактных тестов, в strict —
зелёные на обоих. Дефекты эталона воспроизведены исполнением и у нас закрыты:
сырые токены в `GET /api/sets`, `env:{"A":1}` → 201, `port:9200` → 201.

**Этап 1 — ядро прокси.** `internal/config`, `internal/downstream`,
`internal/mcpserver`, `internal/registry`. Ворота — настоящий бинарник и
настоящий stdio-downstream (`e2e/proxy_test.go`).

**Этап 2 — OAuth.** `internal/oauth` (хранилище токенов, loopback-приёмник,
фабрика `auth.AuthorizationCodeHandler`, `persistingSource`) подключён к
`downstream.Connector`. Сквозной тест против фейкового AS: первый вход — браузер
+ DCR, второй — без браузера, третий — refresh по истечении.

**Этап 3 — HTTP-транспорт.** `internal/httplisten`: stateless `2026-07-28` тем
же обработчиком, что legacy 2025-06-18; bearer fail-closed (кроме открытых
наборов через `allowAnonymous`); `Host`/`Origin` по `allowedHosts`
(пустой список = loopback); лимит 4 МиБ; `/healthz` публичный.

**Этап 4 — менеджер.** `internal/manager`: супервизия набора (spawn без shell,
готовность по TCP, рестарт с backoff, SIGTERM → SIGKILL, лог с ротацией),
материализация `servers.json`, цепочка секретов OpenBao → `env.json` → env
процесса, auth (none/proxy/password/оба, scrypt, cookie с HMAC), HTTP API по
контракту, `internal/atomicfile` для всех записей.

Проверено вживую: `panel` → создать сервер и набор → `start` → набор на 9100 →
`invoke_command echo` возвращает «привет» → `/stats` показывает вызовы по
клиентам (`opencode/2.2.6` и `hermes/1.2` — раздельно) → `stop` гасит процесс.
Открытый набор (`"open": true`) стартует без ключа.

## Этап 5 — сделано

- Панель: `web/` (index.html, app.css, app.js, favicon) вшита в бинарь
  (`web/embed.go`, `internal/manager/panel.go`), CSP со внешними css/js,
  старые шаблонные маршруты `^/$` и `^/ui` удалены. Живая проверка на
  `127.0.0.1:9096`: заголовок, набор, мобильная ширина 400 px без переполнения.
- `mcprig init --client opencode|claude|codex --set <id> [--remote --key]`
  печатает фрагмент конфига, на диск ничего не пишет.
- Счётчики вызовов: `internal/stats` (потолки меток и счётчиков, p50/p95,
  сервер в ключе) плюс `/stats` набора.
- `GET /api/calls?set=&limit=` — таблица вызовов: панель собирает `/stats`
  запущенных наборов (2 с таймаут, bearer из реестра, у открытого без ключа),
  `limit` 50/500, недоступный набор — только id в `unreachable`. Проверено
  вживую: набор `real` (serena, socraticode, xerj) → строка вызова в таблице.
- `/stats` открытого набора отдаёт редактированный снимок (без текстов ошибок
  и меток клиента) вместо 403 — иначе панель не могла показать открытые наборы.
- Ошибка инструмента (`isError` в ответе апстрима) теперь считается провалом:
  счётчик `failures`, `failed` в хвосте, текст — только закрытому набору.

## Ворота (зелёные на `7c2279e`)

```bash
go build ./... && go vet ./... && go test ./... -race -count=1 -p 1   # 186 тестов, 13 пакетов
E2E_BASE=http://127.0.0.1:9093 E2E_STRICT=1 ./scripts/contract-e2e.sh  # PASS против своей панели
```

`-p 1` обязателен: `internal/manager` и `e2e` поднимают настоящие наборы в общем
диапазоне 9100–9199 и при параллельном прогоне пакетов отбирают порт друг у друга.
Против TS-эталона (`127.0.0.1:9091`) контракт гоняется с `E2E_STRICT=0`: три
известных дефекта эталона (токены в `/api/sets`, `env:{"A":1}`, порт 9200).
