# Текущий этап

**Этап 0: контрактный e2e против эталона**
**Статус:** в работе
**Дата:** 2026-11-08

## Цель

Зафиксировать поведение TS-менеджера исполняемым скриптом, чтобы «Go-версия
готова» проверялось сравнением с эталоном, а не мнением.

## Ворота

```bash
bash scripts/contract-e2e.sh
```

Скрипт поднимает (или принимает уже поднятый) эталонный менеджер и проверяет
контракт по HTTP: коды ответов, обязательные поля, инварианты безопасности.
Работает против любого `BASE` — сначала против TS-эталона, потом против Go.

Обязательные проверки:

- `GET /healthz` без авторизации → `200 ok`.
- `GET /api/state` под auth → наборы и серверы без сырых токенов.
- `GET /api/sets` без auth → `401`, не `200`.
- `POST /api/servers` с `env:{"A":1}` → `400`; с именем `UPPER` → `400`.
- `POST /api/sets` с портом 9200 → отказ (диапазон 9100–9199).
- Жизненный цикл набора: create → start → `GET /api/sets/:id/servers` → stop.
- `GET /api/sets/:id/servers/:name/logs` → список строк, не весь файл.
- `POST /api/import` формата `{"mcpServers":{…}}` → `{added,skipped}`.
- Секреты: `GET /api/env` отдаёт имена и признак «задана», без значений.

## Проверяет человек

- Скрипт падает на эталоне ровно там, где ревизия 2026-11-04 нашла дефект
  (auth, allowlist env), и эти пункты помечены `EXPECT_FAIL` — они станут
  обычными проверками для Go.
