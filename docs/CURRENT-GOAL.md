## Жалоба Hermes: набор `ha`, qbittorrent (2026-11-09)

Набор `ha` (`:9102`, 8 серверов) отдавал `qbittorrent` с ошибкой
`context deadline exceeded`; руками тот же сервер отвечал на `initialize` за
0.9 с. Дело не в окружении: go-sdk v1.8.0 открывает сессию методом
`server/discover` (SEP-2575), а сервер собран на Python SDK `mcp` 1.9.0, где
такого метода нет — pydantic отбивает запрос `ValidationError` и приёмный цикл
умирает, не ответив; stderr прокси не читает, отсюда только 15-секундный
таймаут.

Исправлено в `connect.go` (тег `v0.3.2`): stdio-сессии идут через `initialize`
с ревизией `2025-11-25`, HTTP — по-прежнему через `server/discover`. Проверено
двумя способами: тест `TestConnectStdioLegacyServer` (сервер, который падает на
`server/discover`, без правки даёт `connection closed: calling "initialize"`),
и живой запуск — набор из одного qbittorrent стал `healthy: true` за 3.5 мс,
`list_commands` отдал 15 инструментов.

Плагин маршрута в зоне Hermes (`~/.hermes/**`) не установлен: файла
`mcprig-route.ts` и подсказки «MCP живёт за mcprig» там нет ни в конфиге, ни в
`plugins/` — текст встречается только в `state.db`/`lcm.db`, то есть в истории
переписки.
